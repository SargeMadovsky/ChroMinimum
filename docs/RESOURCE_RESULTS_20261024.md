# Результаты: преимущества CM в запуске и ресурсах

2026-10-24, Ryzen 7 3700X / 32 GiB / RX580 / Windows 10. Основная серия
в тестовой Windows-учётке завершилась за 47 мин 32 с. Все 75 измеряемых
попыток приняты: по 10 startup и по 5 idle/video/game на каждый браузер.
Три подготовительных запуска не входят в эти 75. TEMP roots всех измеряемых
запусков соответствуют тестовой учётке, не рабочей учётке технических пилотов.

**Гипотеза о меньших накладных расходах CM частично подтверждена для этих
сборок и сценариев.** Запуск быстрее обоих соперников; private bytes ниже
в простое и игре. Во время видео private bytes выше, а игровой CPU выше UC.
Всеобщее преимущество по производительности из этого не следует.

## Запуск и private bytes

Медианы повторов; MiB = 1 048 576 байт. Private bytes — выделенная приватная
память процессов, это не общий физический расход RAM вместе с GPU и ОС.

| Показатель | CM | UC | Chrome |
|---|---:|---:|---:|
| Запуск до готовности HTML, мс | 312 | 380 | 703 |
| Private bytes: простой, MiB | 201,3 | 260,0 | 331,7 |
| Private bytes: видео, MiB | 356,4 | 333,7 | 326,2 |
| Private bytes: игра, MiB | 317,3 | 342,4 | 351,4 |

- Запуск CM короче на 67,5 мс / 17,8% против UC и 390,8 мс / 55,6% против
  Chrome. CM быстрее в 10/10 сопоставленных кругов для обоих соперников.
  Полные диапазоны не перекрываются: CM 305,9–329,2 мс, UC 369,7–405,3 мс,
  Chrome 647,5–743,4 мс. Это устойчивое различие в этой серии.
- В простое CM выделяет на 58,7 MiB / 22,6% меньше UC и на 130,3 MiB / 39,3%
  меньше Chrome. Во всех 5/5 кругах память CM ниже каждого соперника;
  диапазоны повторов также не перекрываются.
- В игре экономия CM — 25,1 MiB / 7,3% против UC и 34,1 MiB / 9,7% против
  Chrome. Ниже в 5/5 кругах; диапазоны не перекрываются.
- Во время видео CM выделяет на 22,8 MiB / 6,8% больше UC и на 30,2 MiB / 9,3%
  больше Chrome. CM выше UC в 4/5 кругах, выше Chrome в 5/5. Преимущество
  по private bytes на видео не подтвердилось. Причина не исследована.

Рабочий набор (working set) даёт другую картину и сохраняется отдельно:

| Сумма working set, MiB | CM | UC | Chrome |
|---|---:|---:|---:|
| Простой | 363,2 | 430,3 | 570,0 |
| Видео | 442,4 | 499,3 | 519,6 |
| Игра | 414,3 | 480,2 | 515,7 |

Сумма working set может повторно учитывать общие страницы разных процессов;
её нельзя объявлять уникальным физическим расходом RAM. Меньший working set
не отменяет большего private commit на видео. Показаны обе метрики, без
выбора только выгодной CM.

## CPU и плавность

100% ниже означает одно полностью занятое логическое ядро; для доли всего
16-поточного ПК нужно делить на 16. Это CPU браузерных процессов в измеряемых
окнах, не общесистемная нагрузка и не энергопотребление.

| CPU, % одного ядра, медиана | CM | UC | Chrome |
|---|---:|---:|---:|
| Простой | 0,12 | 0,18 | 3,56 |
| Видео | 1,13 | 1,13 | 3,26 |
| Игра | 23,93 | 21,42 | 23,98 |

На видео CPU CM и UC практически одинаков по медианам; диапазоны сильно
перекрываются. Игровой CPU CM практически равен Chrome, но выше UC на 11,8%
относительно его медианы; CM выше UC во всех 5 сопоставленных кругах.
В долях всего ПК это 1,50% у CM против 1,34% у UC, разница 0,16 процентного
пункта. Это не свидетельствует о худшей плавности CM.

На видео и в простое CPU CM ниже Chrome во всех 5 кругах каждого сценария.
Однако абсолютные нагрузки малы: на видео 0,071% всего ПК у CM и 0,204%
у Chrome. Разницу нельзя подавать только крупным относительным процентом.
Разница idle CPU CM/UC слишком мала и нестабильна: CM ниже лишь в 3/5 кругов,
диапазоны перекрываются; преимущество здесь не установлено.

Во всех 15 видеопопытках dropped=0, waiting=0, stalled=0. Во всех 15 игровых
попытках p99 render-loop интервала ≈6,2 мс, интервалов >2 и >4 периодов
165 Hz нет; используется ANGLE RX580/D3D11. Проверенная плавность сохранена.
Render callbacks не являются внешним измерением физического показа кадров,
а сцена около частоты экрана не определяет запас производительности.

## Проверка данных и ограничения

- Проверены хеши 16 файлов упакованного измерителя. Все сохранённые resource
  summary пересчитаны из raw, video/game behavior пересчитаны прежними
  измерителями; startup сверены с host-ready timestamps. Агрегаты пересчитаны.
  Несовпадений нет. У всех 75 browser lifecycle exit=0.
- Для всех 45 ресурсных попыток CPU дополнительно сверён независимым способом:
  разность сумм накопленных CPU ledger на последнем/первом отсчёте. Сошлось.
  Handles сохраняют конечный CPU уже обнаруженных завершившихся процессов.
- Учёт охватывает процессы текущего сеанса с exe внутри каталога runtime.
  Процессы вне каталога и полностью между секундными отсчётами не учтены.
  Это ограничение, а не гарантия полного процессного дерева/всех служб продукта.
- Расход наблюдателя: медиана 1,31% одного ядра (диапазон медиан попыток
  0,99–1,84%), private bytes около 72,9 MiB; медиана чтения 10,5 мс.
  Он не включён в память/CPU браузера и не вычитается из результата. Возмущение
  от наблюдателя отдельно не измерялось; особенно осторожно трактовать idle CPU.
- ОС сообщает 2560×1440@165 Hz. Перед серией CPU snapshots 2/2/1%.
  В системном списке есть фоновые службы/программы; он не содержит SessionId
  и не доказывает отсутствие фонового влияния либо работу иной пользовательской
  сессии. Непрерывного измерения фоновой нагрузки здесь нет.
- Подготовленные синтетические профили клонировались в TEMP на C:; кэш ОС
  прогрет. Измеряется готовность локального HTML после двух rAF и HTTP-сигнала,
  не холодный запуск и не готовность произвольного интернет-сайта.
- CM Chromium 154, UC/Chrome 155. Сравниваются конкретные продукты целиком;
  разницу нельзя полностью приписать оболочке. GPU load, VRAM, энергопотребление,
  одинаковость decoder backend и старые ПК этой серией не проверены.
- Порог практической пользы владелец решил выбрать после измерений. Формальные
  проверки значимости/эквивалентности не были заранее назначены; описание
  повторяемости не подменяет их.

## Решение по гипотезе

У CM есть измеряемые преимущества в запуске и памяти при простое/игре на этом
ПК. Утверждение «отсутствие большого интерфейса вообще ничего не даёт»
этой серией не поддерживается; причинную долю интерфейса отдельно не выделяли.
Утверждение «CM быстрее и экономнее всех во всём» тоже не поддерживается:
видео расходует больше private bytes, UC использует меньше игрового CPU.

Следующий шаг — оценить, достаточно ли владельцу выигрыша около 68 мс против
UC и 59 MiB в простое / 25 MiB в игре, либо выбрать ограниченную оптимизацию
видеопамяти процессов. Повтор всей серии сейчас не требуется.
