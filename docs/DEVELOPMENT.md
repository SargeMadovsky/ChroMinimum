# ChroMinimum

Проект минималистичного открытого браузера: Chromium для современного веба, оболочка преимущественно на Rust, дополнительные функции через модули и расширения.

**Состояние на 19 октября 2026 года:** создан первый Windows x64 прототип на Rust + CEF: одно окно с нативной панелью навигации, отдельный профиль и встроенный компонент просмотра PDF Chromium. Это техническая сборка, не завершённый браузер. Совместимость расширений пока не исследована; CEF выбран предварительно для базового прототипа.

## Сборка и запуск

После [подготовки Windows](SETUP_WINDOWS.md) выполните из корня проекта:

```powershell
.\scripts\build.ps1
.\scripts\run.ps1 -Url 'https://example.com/'
```

Готовый файл: `target/bundle/chrominimum.exe`. Можно запускать двойным щелчком; открывается пустая страница. Введите адрес в верхней строке. Храните всю папку bundle рядом с exe: это многокомпонентная поставка Chromium, один exe отдельно не работает.

Локальный PDF:

```powershell
.\scripts\run.ps1 -PdfPath 'C:\Documents\example.pdf'
```

Собственная панель содержит «Назад», «Вперёд», «Обновить/Остановить» и адресную строку. Enter открывает введённый адрес; без схемы добавляется https://. Поисковые запросы пока не поддерживаются. Ctrl+L выделяет адрес, F5 обновляет страницу. Повторная передача URL уже открытому экземпляру пока не реализована; перед запуском с другим URL закройте первое окно.

Окно поддерживает стандартные кнопки Windows: свернуть, развернуть/восстановить и закрыть. Размер меняется перетягиванием границ и углов; минимальный размер — 640×360, начальный — 1100×760. Панель и страница подстраиваются под доступное место.

Адресная строка занимает всю свободную ширину панели после кнопок и растягивается вместе с окном.

Иконка приложения и окна создана из пользовательского assets/chrominimum.svg; ICO содержит размеры 16–256 px. SVG сохранён в исходном виде, свободные поля убраны только в производных иконках.

Автоматическая проверка локального HTML/JavaScript, создания панели и закрытия:

```powershell
.\scripts\smoke.ps1
```

Тест открывает окно примерно на 30 секунд и использует `target/bundle/profile-smoke`; обычный профиль — `target/bundle/profile`. Проверяются ненулевые размеры и состояние отрисовки элементов панели, обработчик Enter, переходы назад/вперёд и reload на двух локальных документах, установка иконок и штатное завершение. Это проверка делегатов и состояния CEF, не имитация реальных нажатий мыши/клавиатуры. Не запускайте smoke одновременно с другим экземпляром. Форматирование и анализ кода: `cargo fmt --all --check` и `cargo clippy --locked --lib --bin bundle -- -D warnings` в Developer PowerShell.

## Ограничения прототипа

Нет панели вкладок, пользовательской платформы плагинов, updater и установщика. Popup заблокированы, что может мешать авторизации на отдельных сайтах. Штатная Chrome toolbar скрыта; используется собственная минимальная панель CEF Views. Поиск, загрузки, разрешения, приватный режим и восстановление после сбоев ещё не приняты. Кнопка остановки подключена к stop_load, но сценарий прерывания медленной сетевой загрузки ещё требует ручной проверки.

Sandbox включён в сборку и используется CEF bootstrap; защитные флаги не отключались. Полный аудит изоляции, исходящих соединений и очистки Google-интеграций не проводился. Внешний вид, ввод, DPI и возможности PDF требуют ручной проверки. Не используйте прототип для важных аккаунтов до завершения приёмки безопасности.

## Основные принципы

- Минимальная базовая установка: окно, адресная строка, навигация и необходимые механизмы безопасности.
- WebExtensions — приоритет совместимости; собственный API дополняет его.
- Цели: MV2 и MV3, динамическая блокировка запросов, установка расширений без обязательного магазина.
- Отключённые дополнительные модули не выполняют фоновую работу.
- Без обязательных аккаунтов, рекламы оболочки и пользовательской телеметрии.
- Производительность и отсутствие нежелательных соединений подтверждаются измерениями.

Первая платформа — Windows x64. Linux, macOS и ARM64 следуют после проверки архитектуры. Команды сборки появятся вместе с реально проверенным прототипом. Собственный код распространяется по MIT.

Текущий приоритет владельца: сначала браузер для сайтов и PDF, одно окно без вкладок и плагинов. Исследование совместимости расширений отложено; оно остаётся условием окончательного выбора архитектуры будущей платформы, но не блокирует базовый прототип.
