# Аудит: что можно вырезать из CEF

Дата: 2026-11-23. База: CEF 154.0.34, Chromium 154.0.8037.98, аргументы
`out/Release_Media_Official_x64`. Контекст: [D047](DECISIONS.md).

**Статус доказательств.** Исходники прочитаны. Вес кода оценён по PDB. Флаги
проверены только через `gn gen`. Ни один вариант не скомпилирован и не запущен,
экономия памяти, запуска и CPU не измерена. Патчи к CEF не применялись.

## Вывод

1. Вырезание модулей мало уменьшит поставку. Самые тяжёлые части (Blink, V8,
   графика) обязательны, а отдельные функции весят 0,2–6 МиБ из ~251 МиБ кода.
2. Вес кода на диске — не то же, что расход памяти и запуск. Более перспективная
   цель — 135 сервисов профиля, которые объявлены создаваемыми вместе с
   профилем. Сколько из них реально работает, нужно измерить запуском.
3. Встроенный менеджер паролей весит ~3,1 МиБ (~1,2% кода). Полное удаление
   дорого и рискованно, отключение настройкой почти бесплатно (см. ниже).
4. Семь GN-флагов можно отключить в первой партии. Каждая смена GN-флагов — это
   широкая пересборка, поэтому их стоит совместить с переходом на новый CEF.

## Кандидаты по риску

### A. Первая партия: GN принимает, потери малы

Эти семь флагов со значением `false` вместе с двумя флагами из группы B прошли
`gn gen` одной конфигурацией.

| Флаг | Что уходит | Проверить после сборки |
|---|---|---|
| `enable_vr` | WebVR/WebXR | `navigator.xr` отсутствует, сайты не падают |
| `enable_openxr` | среда OpenXR | то же |
| `enable_browser_speech_service` | браузерный сервис речи | Web Speech API, субтитры |
| `enable_media_remoting` | удалённое воспроизведение | обычное видео, кодеки |
| `enable_paint_preview` | снимки страниц | печать, сохранение страницы |
| `enable_pdf_save_to_drive` | сохранение PDF в Google Drive | просмотр и сохранение PDF |
| `enable_pdf_translation` | перевод в PDF | просмотр PDF |

### B. Только по решению владельца

| Флаг | Почему не в первой партии |
|---|---|
| `enable_reporting` | Убирает Reporting API и NEL. Это меньше фоновых отчётов сайтам, но меняет поведение веб-платформы. |
| `enable_bound_session_credentials` | Защита сессий Google от кражи cookie. Выключение ослабляет безопасность, рекомендую оставить. |

### C. Нужны правки GN

`gn gen` падает на `assert`, потому что зависимые цели всё ещё ссылаются на
модуль. Объём правок не оценён.

- `enable_compose` — помощник письма.
- `enable_lens_desktop` — Google Lens.
- `enable_on_device_translation` — локальный перевод.
- `enable_speech_service` — локальная речь.
- `enable_supervised_users` — родительский контроль. Падает в
  `chrome/test/BUILD.gn`, цель тестов.
- `enable_screen_ai_service` — OCR и извлечение текста. Это функция доступности,
  поэтому удалять только после отдельной оценки.

### D. Рантайм: сервисы профиля

135 фабрик объявляют `ServiceIsCreatedWithBrowserContext() = true` (поиск по
исходникам). Среди них glic, Lens, покупки, enterprise-отчёты, телеметрия Safe
Browsing, вход в аккаунт, родительский контроль, Media Router и проверки паролей.
Многие могут возвращать `null` в рантайме.

Следующий шаг здесь — не патч, а замер: список реально созданных сервисов, их
время и память на чистом профиле. Патчить стоит только то, что покажет замер.

### E. Не трогать

- Sandbox, изоляция сайтов, проверка сертификатов, Safe Browsing (AGENTS.md).
- `enable_mdns`: GN проходит, но mDNS скрывает локальные IP в кандидатах WebRTC
  (`peer_connection_dependency_factory.cc`). Отключение может раскрыть их сайтам.
- Требования `cef/BUILD.gn`: `enable_print_preview`, `enable_widevine`,
  `enable_cdm_host_verification`, `enable_cdm_storage_id`,
  `alternate_cdm_storage_id_key`, `enable_rlz`.

RLZ остаётся в сборке, потому что CEF связывает его с идентификатором хранилища
Widevine CDM. По исходникам небрендированная сборка считается organic и не
регистрирует брендовые события и финансовый ping. Сетевым журналом это **не
проверено**, такую проверку стоит включить в приёмку.

## Менеджер паролей

Факты по исходникам:

- GN-флага нет.
- Хранилище открывается при запуске (`Login Data`, `Login Data For Account`).
- На каждую вкладку создаются `ChromePasswordManagerClient` и
  `ChromePasswordReuseDetectionManagerClient`.
- В рендерере `PasswordAutofillAgent` и `PasswordGenerationAgent` — аргументы
  конструктора `AutofillAgent` каждого фрейма.
- На `password_manager::` ссылаются 209 файлов `.cc` в `chrome/browser`.
- Настройка `credentials_enable_service=false` или политика
  `PasswordManagerEnabled` только перестают предлагать сохранение. **Уже
  сохранённые пароли продолжают подставляться**, хранилище остаётся.

| Вариант | Выигрыш | Цена и риск |
|---|---|---|
| 1. Настройка: не предлагать сохранение | нет экономии, нет запросов на сохранение | без патча CEF, обратимо |
| 2. Патч: не открывать хранилище, отключить клиенты и агенты | ожидается немного памяти и запуска, не измерено | средний патч рядом с Autofill, конфликты при обновлениях CEF |
| 3. Полное удаление кода | до ~3,1 МиБ кода | сотни файлов, самый дорогой патч в сопровождении, высокий риск сломать Autofill |

Любой вариант, закрывающий доступ к хранилищу, пересматривает решения
[D029 и D031](DECISIONS.md), где локальное хранилище сохранено. Пользователям
alpha с сохранёнными паролями нужен экспорт и предупреждение до выключения.
Замену расширением обещать нельзя без испытания (PRODUCT.md).

**Рекомендация:** вариант 1 сейчас. К варианту 2 переходить, если замер покажет
заметную цену хранилища и клиентов на вкладку. Вариант 3 не делать.

## Объём патча вкладок (D047, путь 1)

По исходникам, без сборки. Публичный API CEF менять не планируется, иначе
понадобятся транслятор, хеш API и новая генерация cef-rs.

- `chrome_browser_host_impl.cc`: окно на Views сейчас принудительно становится
  `TYPE_POPUP`, а у такого окна нет полосы вкладок.
- `CefBrowserPlatformDelegateChromeViews`: установка view, создание WebContents,
  уничтожение браузера и закрытие окна рассчитаны на один браузер.
- `CefBrowserViewImpl`: одно поле `browser_` и проверка «Cannot add multiple» в
  `AddedToWidget`.
- `ChromeBrowserHostImpl::WindowDestroyed`.
- Команды Chrome для вкладок закрыты признаком `kFeatureTabStrip`.

Основа уже есть: для окон Chrome без Views CEF создаёт отдельный host на каждую
вкладку. Проверить придётся фокус, заголовок, панель поиска, PageInfo (D043),
панель загрузок (патчи 0005 и 0014), полноэкранный режим, диалоги,
`beforeunload`, popup, DevTools и масштаб. В оболочке нужны `PageId` и
`PageState`.

## Рекомендуемый порядок

1. Перенести патчи на актуальный стабильный CEF. В этот же полный билд включить
   группу A.
2. Снять замер сервисов профиля и решить по группе D и варианту 2 для паролей.
3. Делать патч вкладок на новой базе, чтобы не переносить его дважды.

Полная сборка заняла 6 ч 17 мин (38 149 шагов), поэтому флаги стоит собирать в
одну партию.

Приёмка каждой партии: размер поставки, запуск, private bytes и CPU простоя
против текущей сборки, смоук, сетевой журнал чистого профиля, проверка кодеков и
расширений.
