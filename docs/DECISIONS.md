# Журнал решений

### D042 — явный Windows-вариант системных кодеков, 2026-11-01

По одобрению владельца проверенный media0011 объединяется с актуальными
загрузками и внешними протоколами. Cargo feature `windows-platform-codecs`
включает платформенный AAC в обычном запуске и дочерних процессах. Default
вариант не меняется. Это вариант для конкретного проверенного ядра, не обещание
совместимости со стандартной CEF DLL. Новых зависимостей, служб и сетевых
соединений нет; численные накладные расходы полной оболочки пока не измерены.
Адаптер изменился, поэтому нужна полная установка/доверенная миграция seed;
обычный core update требует побайтно прежний адаптер. Локальный архив проверен
с одноразовым ключом, публичного выпуска/правового заключения этим нет.
[Проверки и ограничения](PLATFORM_CODECS_RELEASE_INTEGRATION.md).

### D041 — штатный Chromium handler внешних протоколов, 2026-10-30

Заменяет D040 по сообщению владельца о зависаниях и явному запросу штатного
поведения Chromium. Удалены MessageBox/ShellExecuteW оболочки; CEF передаёт
неизвестную внешнюю схему через ResourceRequestHandler/OnProtocolExecution в
ExternalProtocolHandler Chromium. Для адресного LoadURL подготовлен0012:
разрешает отсутствие живого документа лишь у доверенного TYPED primary main-frame
запроса вне fenced tree, включая HTTP redirects. TYPED подтверждён проверками
Chromium renderer IPC; истёкший renderer LINK остаётся заблокирован. Обычные
Chrome consent/policies сохраняются.0013 не даёт CEF повторно превращать уже
распознанный numeric opaque URI в HTTP host:port.
Popup с gesture направляются в исходном живом документе через экранированное
присваивание location.href; реальный origin/sandbox сохраняются. Причина: штатный UI и асинхронный OS lookup вместо блокирующего
Win32 диалога. Последствия: нужна пересборка CEF; её высокая стоимость заранее
сообщена владельцу. Native dialog обычной ссылки/реальная передача тестовому
handler подтверждены. Матрица выявила слишком строгую проверку opaque origin
после адресного HTTP redirect; исправленный кандидат прошёл19/19 сценариев
2026-10-31, включая этот redirect, numeric URI, sandbox и shutdown.
Основная установка не обновляется. [Доказательства и ограничения](EXTERNAL_PROTOCOLS.md).
2026-10-31: после проверки и одобрения владельца патчи обязательны в обоих CEF
build scripts. Выпущен локальный portable ZIP с теми же проверенными бинарниками;
installer/media-приёмка и публичная публикация не расширены.

### D040 — общий системный запуск внешних протоколов Windows, 2026-10-30

Заменено D041 после сообщения владельца о частичных зависаниях. Конкретная
причина зависаний не установлена; блокирующий путь удалён из текущего кода.

По запросу владельца добавлен общий путь внешних схем без списка приложений:
явное действие → системное подтверждение оболочки → ShellExecuteW.
Причина: CEF Chrome path зависит от initiator document и не покрывает одинаково
адресную строку и перенос popup через LoadURL. Собственный MessageBox выбран
для единого пути без пересборки CEF; это не штатный пузырь Chrome. Последствия:
нет постоянных разрешений, Linux/macOS и редиректы без gesture пока не поддержаны;
поведение требует runtime-приёмки. Расходы заранее обсуждены, сравнительных
замеров нет. [Границы и проверки](EXTERNAL_PROTOCOLS.md).

### D039 — экспериментальный системный AAC для WebAudio, 2026-10-29

По поручению владельца реализуется локальный Windows-прототип: AAC после
отказа синхронного reader направляется в существующий Mojo/MF GPU decoder.
Владелец запроса размещён в Blink platform/media; общие demux, timestamps и
AAC trimming остаются в media/filters. PCM передаётся между последовательностями
как media::AudioBus, а Blink AudioBus создаётся перед штатным ресемплингом.
Причина: сохранить sandbox и включить системный AAC без встроенного AAC decoder.
Последствия: новый async путь, IPC и копия encoded input при fallback; отмена
при teardown контекста, по одному пакету в работе. 30-секундный timeout является
только ограничением прототипа. Синхронный Platform API и остальные форматы
сохранены. Release-приёмки нет; стоимость запуска/CPU/памяти ещё не измерена.
[Исходники, проверки и ограничения](WEBAUDIO_PLATFORM_AAC_PLAN.md).


### D038 — native anchor загрузок: подготовленное решение, 2026-10-25

Предложено после скриншота владельца, но не включено в проверенный runtime:
не менять экранные координаты OS-окон, а передать штатной карточке Chromium
нашу кнопку как views::BubbleAnchor через стабильный View ID. При наличии
кнопки подавить flight animation; без неё оставить обычный Chrome fallback.
Публичный CEF API не расширяется; вводится внутренний контракт ядра/оболочки
и небольшой version-pinned патч. Причина: корректная привязка при собственной
панели; следствия: пересборка CEF, повторная приёмка и сопровождение патча.
К затратной сборке ещё не приступали; ожидаемые расходы раскрыты в
[подготовке](DOWNLOAD_BUBBLE_ANCHOR.md). D037 остаётся текущим проверенным UI.

### D037 — штатный Chrome UI загрузок вместо собственного окна, 2026-10-25

Заменяет часть D036 о загрузках по предложению владельца после ручного скриншота:
собственное окно некорректно отображалось в тёмной теме и дублировало карточку
Chromium. Используется готовый Download UI Chrome runtime CEF; собственный
DownloadHandler/окна удалены. Кнопка панели и Ctrl+J открывают chrome://downloads
в текущей странице, история навигации возвращает сайт. Настройки сохранения
штатные; новое окно/вкладка не создаются. Исправление HTTP(S)-ссылок D036 сохранено.
Причина: меньше собственного кода и согласованный с Chromium вид/жизненный цикл.
Следствия: зависимость от WebUI выбранного CEF; привязка всплывающей карточки
к скрытой панели остаётся отдельной задачей. Ожидаемые расходы обсуждены;
DLL уменьшена на 72704 байта, RAM/CPU/startup не измерены. Новых зависимостей,
служб и запросов оболочки нет. [Проверки и ограничения](LINKS_DOWNLOADS.md).

### D036 — переходы в одной странице и окна загрузок, 2026-10-25

По сообщению владельца о GitHub-ссылке явные HTTP(S)-переходы, запрашивающие новое
окно, направляются в текущую страницу. Popup без действия пользователя остаются
заблокированы. Для минимальных загрузок выбран предложенный владельцем вариант
отдельного окна в духе IE 5.5/6: штатное сохранение CEF, прогресс, отмена,
результат и открытие папки. Собственный менеджер истории/восстановления не добавлен.
Причина: работоспособные базовые ссылки и видимая загрузка без панели вкладок.
Следствия: новое окно на файл, временное состояние; совместимость popup-авторизации
этим не обещается. Новых зависимостей/служб нет, расходы обсуждены; сравнительные
замеры не проведены. Приёмка GUI и штатного диалога остаётся открытой; computer-use
запрещён владельцем. [Реализация, доказательства и ограничения](LINKS_DOWNLOADS.md).

### D035 — media-состав следующего Windows-кандидата, 2026-10-24

Для alpha.8 сохраняется принятый official Release media CEF с ядром
ef8d6219fb826b586ca25b60f6583ba0c1453cb9172051521a02f5fb8057e020;

Публичная готовность требует отдельного закрытия media distribution и

### D032 — экспериментальное ядро с H.264/AAC, 2026-10-21

Дополнение 2026-10-23: по согласию владельца проверена штатная official Release
конфигурация, поскольку non-official preview дал большие расходы. Сохранены
BRP/GWP-ASan, diagnostic instance tracer выключен штатной веткой CEF, ThinLTO
включён, PGO=0. Media/fullscreen/TLS/PDF/sandbox прошли; в трёх парных замерах
private bytes/CPU близки к stock. Публичный канал пока не меняется;
[результаты, воспроизводимость и ограничения](CEF_MEDIA_RELEASE_EXPERIMENT.md).

Дополнение 2026-10-22: первичная компиляция завершилась, началась приёмка alpha.8.
Подтверждены локальные MP4/WebM и AAC в PCM, но TLS-тест обнаружил deadlock
отладочного InstanceTracer через free hook GWP-ASan. В эксперимент добавлен
закреплённый патч 0003: узел таблицы уничтожается после снятия mutex, без
отключения BRP/instance tracing/GWP-ASan. USER32/SHELL32 оболочки загружаются
отложенно для sandbox renderer; метрики RecordLockAcquisitionTime отключены
из-за отдельной рекурсии аллокатора. Публичная поставка по-прежнему не меняется.
Форма текущей приёмки — отдельный portable preview; канал stock-обновлений к нему
не подключается. [Подготовка alpha.8](RELEASE_ALPHA8.md), [карта знаний](CEF_KNOWLEDGE.md).

После диагностики видео владелец явно разрешил «собрать и проверить экспериментальное
ядро». Уточняет D031 только для отдельного эксперимента; поставка alpha.7 и канал
обновлений остаются stock. Контрольный H.264/AAC MP4 на alpha.7 завершился
DEMUXER_ERROR_NO_SUPPORTED_STREAMS, контрольный VP9/Opus воспроизводился.
Принят эксперимент с закреплённым CEF/Chromium и
`proprietary_codecs=true ffmpeg_branding=Chrome`, без патча ListAccounts.
Для воспроизводимости MIDL на ru-RU добавлен сборочный пересчёт хеша имени
библиотеки по объявленной LCID через системный Windows API. Исходник helper
закреплён SHA-256; изменяемый хеш обязан совпадать с вариантом пользовательской
локали. Эталонные файлы, IDL-интерфейсы и штатное побайтовое сравнение сохраняются.
На tracing_service и updater_legacy пересчёт дал точный upstream TLB; исходный
канонический TLB сохраняется. Перед полной компиляцией проверяются MIDL-цели.
Это сборочный патч, не изменение функциональности браузера.
Стоимость CPU/RAM/диска/загрузок исходников обсуждена до согласия; размер поставки,
старт и ресурсы воспроизведения ещё не измерены. Постоянная служба не требуется.
До распространения нужны проверка условий лицензирования и полная приёмка ядра,
включая sandbox/TLS и подписанную доставку. Установка владельцу не разрешена этим
экспериментом автоматически. [Диагностика](MEDIA_DIAGNOSIS.md).

### D031 — готовый минимальный CEF вместо собственного форка, 2026-10-21

Владелец выбрал стандартную бинарную поставку CEF, чтобы сопровождение проекта
оставалось преимущественно работой над оболочкой. Собственная сборка и патч
ListAccounts остаются исследованием; их доставка и перевод workflow на сборку
Chromium отложены. Пробная компиляция остановилась с ошибкой и не возобновляется.
Для alpha.7 используется проверенный stock CEF 154.0.34 и прежний baseline.

Сохраняются уже проверенные настройки запрета внешних предустановленных
расширений, AI eligibility и серверного Autofill. Менеджер паролей сохранён;
ListAccounts и прочие неустранённые upstream-запросы фиксируются как ограничения,
отсутствие всей фоновой сети не заявляется. Приоритет — совместимость и
своевременные проверенные обновления готового CEF. Новых зависимостей браузера,
служб и сетевых соединений это решение не добавляет. В alpha.7 входят общие
UI-изменения и финальный логотип; измеренного ускорения от них не заявляем.

### D030 — исправление стартового ListAccounts в исходном CEF, 2026-10-21

Подготовлен кандидат патча Chromium 154: убрать ListAccounts из
IdentityManager::OnNetworkInitialized и включить cache-only feature только
в соответствующей собственной сборке. Причина: стек показал два стартовых
пути, и один флаг заменяет первый вторым. Диагностическая интервенция дала
0 запросов без изменения файла DLL. Исходный патч применён к копии и проверен
по SHA, но CEF не собран. [Доказательства, ограничения и toolchain](ACCOUNTS_ROOT_CAUSE.md).
Владелец разрешил установку Build Tools 2026/SDK 28000 рядом с прежними инструментами. Бинарные
горячие патчи не используются для доставки, прежний baseline updater сохраняется.

Владелец разрешил пробную сборку исходников и включение общих UI-изменений.
Добавлены закреплённый рецепт и проверка применения патча с отказом при изменении
версии/исходника. Патч применяется на стороне сборки, пользователь получает
готовый runtime. Текущий workflow ещё получает stock CEF; перевод канала и
новый baseline допустимы после приёмки собственного ядра.
[Состояние сборки и ограничения](CUSTOM_CEF_BUILD.md).

### D027 — запрет автоматических предустановленных расширений, 2026-10-20

Принято для текущего прототипа: `disable-default-apps` в browser command line.
Точная версия Chromium прекращает создание провайдеров до Windows registry,
предустановок и external component extensions; enterprise providers исключены
из этого запрета. Причина — подтверждённая автоматическая загрузка Adobe CRX
из чужой регистрации Chrome. Общий запрет extensions и component updater не
применяется. Последствия и три runtime-проверки: [EXTERNAL_EXTENSIONS.md](EXTERNAL_EXTENSIONS.md).
Будущая пользовательская установка расширений требует самостоятельных тестов;
совместимость MV2/uBlock Origin этим решением не доказана. Основной alpha.6
остаётся прежним до следующего полного установщика.

Дата исходных записей: 2026-10-19. «Принято» означает направление проекта; «кандидат» требует эксперимента.

## Как изменять решения

### D026 — белая подложка прозрачного HTML, 2026-10-20

PageDelegate поддерживает белый BrowserView background при смене темы Views,
с явным white в CEF Settings/BrowserSettings. Причина: прозрачный документ
показывал тёмный слой UI и чёрный текст становился нечитаемым. Авторские CSS,
системная рамка и тёмная панель не переписываются. Проба внутреннего Emulation
удалена; итог использует обычный CEF Views API. Снимки композиции и EN/RU
TestInstall прошли. Отдельный ephemeral CDP допускается только при явных
--smoke-test --test-cdp для диагностических снимков собственных фикстур.
[Аудит и ограничения](BACKGROUND_NETWORK_AUDIT.md).

### D025 — передача цели при relaunch без разрешения Chromium-флагов, 2026-10-20

После сброса CEF command line восстанавливается только URL, ранее разобранный
оболочкой, и только для browser process. Причина: ProcessSingleton передавал
пустую цель и второе окно становилось about:blank. command_line_args_disabled=1,
sandbox и TLS остаются включёнными. Дополнительный IPC/служба не создаются:
используется штатный CEF relaunch. Проверка сравнивает фактический URL второго
PDF, а не только количество окон/событий загрузки. [Интеграция и ограничения](UI_INTEGRATION.md).

### D024 — доверенный baseline полного установщика, 2026-10-20

Миграция D023 реализована через installer-seed.json и его идентичность в state:
полный установщик может выбрать свой seed с явно проверенным security sequence,
сохранив highest и не понижая min_safe. Уровень 1 принят только для закреплённых
CEF/bootstrap хешей, совпавших с установленным v1; другой engine блокирует staging.
Preflight до копирования и повторная проверка после него требуют свободных leases,
проверка хешей предшествует атомарной записи state. Старые ядра не удаляются.
Причина: технический sequence=0 у seed не должен требовать удаления security floor.
Следствия: новое поле state, старый launcher откажется его читать; весь setup не
становится атомарным, после прерывания может потребоваться повторная установка.
[Проверки, расходы и ограничения](INSTALLER_SEED_MIGRATION.md).

### D023 — привязка адаптера format=1 к установщику, 2026-10-20

Для Windows engine-only обновлений принято сравнение размера/SHA-256 DLL с
core/seed до публикации и перед запуском vN, включая восстановление. Причина:
старый подписанный пакет не должен отменять hardening адаптера из нового setup.
Следствия: seed доверен как часть полной установки, изменение DLL требует
полного установщика; безопасность от замены launcher/seed локальным атакующим
этим не обеспечивается. Legacy active/pending с другой DLL отклоняются, но
их миграция с сохранением security floor — отдельный этап перед основным alpha.4.
Проверки, расходы и ограничения: [UPDATER_ADAPTER_BINDING.md](UPDATER_ADAPTER_BINDING.md).

### D022 — обязательная Windows network sandbox, 2026-10-20

Статус: исправление источников и изолированная приёмка, не выданное владельцу
обновление. Для native x64 Windows build 19041+ явно включается NetworkServiceSandbox,
core получает только read/execute AppContainer, повторный запуск NetworkService
без sandbox запрещается до spawn. Неподдерживаемые ОС/ARM64 emulation отклоняются.
Причина: upstream feature disabled по умолчанию и автоматический fallback при
ошибке доступа executable, подтверждённые исходником и токенами. Последствия:
минимум ОС уточнён относительно первого setup, при security-отказе собственный
browser process завершается без обычного shutdown, нужно сохранить эту гарантию
при обновлении адаптера. Выпуск основного setup отложен до совместимости updater;
рабочий канал не менялся. [Доказательства и стоимость](NETWORK_SANDBOX.md).

### D021 — первый per-user Windows-инсталлятор, 2026-10-20

По запросу владельца: офлайн Inno Setup, программа в LocalAppData/Programs/ChroMinimum,
данные отдельно в LocalAppData/ChroMinimum, только HKCU-регистрация HTML/HTM/PDF
без смены UserChoice. Причина: дать владельцу установить прототип и выбирать его
обработчиком файлов, проверять SSD/HDD отдельно. Английский fallback обязателен,
русская локализация опциональна; остальные части CEF не объявлены съёмными.
Первый setup использует прежний format=1, не переключая рабочий канал на непроверенную
модульную публикацию D020. Следствия: полные обновления могут вернуть лишние языки,
нужны отдельные миграция/очистка, визуальная приёмка и модульная доставка.
Установка/удаление проверяются через отдельную TestInstall-идентичность;
владельческую установку выполняет сам владелец. [Подробности](WINDOWS_INSTALLER.md).

### D020 — отдельное состояние модульной транзакции, 2026-10-20

Статус: экспериментальная реализация для локальной приёмки. До миграции рабочего
загрузчика модульные комплекты используют component-state.json и каталоги
component-core с идентичностью receipt, сохраняя core-state.json/format=1.
Причина: разные языковые наборы возможны для одной sequence; прежний vN этого
не выражает, а преждевременное изменение рабочего указателя рискует нарушить
доставку обновлений. Следствия: отдельная интеграция launcher/healthy/lease,
проверка миграции и очистки; второй сетевой канал или постоянная служба не созданы.
Подтверждены локальные API-транзакции, не реальный запуск через этот протокол.
Подробности: [INSTALLATION_COMPONENTS.md](INSTALLATION_COMPONENTS.md#локальная-транзакция-модульного-комплекта).

Прогресс 2026-10-20: явный --launch-components связан с браузером через readiness
pipe и передачу locale/lease; изолированная E2E-проверка подтвердила реальный
запуск и смену языка. Обычный загрузчик format=1 не переключён, миграция и новый
сетевой канал остаются отдельными задачами.

Прогресс 2026-10-20: добавлен явный --fetch-components с локальным подписанным
каталогом и HTTPS-загрузкой только выбранных архивов в новый кэш; после сети
prepare повторно проверяет актуальные ограничения. Это не новый рабочий канал.
Потоковая загрузка проверена на loopback HTTP с тестовым транспортом; сквозная
HTTPS-доставка реального CEF этой командой ещё не проверена.

### D019 — выбор компонентов установки, 2026-10-20

Статус: направление принято по запросу владельца; реализация пока ограничена
проверкой конфигурации, подписанного каталога и планом. Малый инсталлятор должен устанавливать обязательное
ядро и выбранные отделимые компоненты, а обновлятор — сохранять выбор. Для первого
шага подтверждены данные локализаций ru/en-US; en-US остаётся резервной зависимостью.
Физическое выделение доступности и словарей ещё не подтверждено и не представляется
готовыми галочками. Причина: минимальная установка без обещания произвольного
разделения libcef.dll. Следствия: новый подписанный каталог, транзакция комплекта
и миграция загрузчика; текущий manifest=1 и рабочий канал пока не меняются.
Контракт и ограничения: [INSTALLATION_COMPONENTS.md](INSTALLATION_COMPONENTS.md).

### D016 — публичная публикация, 2026-10-19

По явному выбору владельца: публичный SargeMadovsky/ChroMinimum, собственный код под MIT. Выпуск — экспериментальный prerelease 0.0.1-alpha.1, без утверждения о завершённой security-приёмке. Локальные отчёты, профили и кеши не публикуются. Linux x64 и macOS ARM64 проходят отдельные сборки и smoke-проверки в GitHub Actions; поддержка не объявляется подтверждённой до фактических результатов.

Новая запись: ID, дата, статус, проблема, варианты, доказательства, выбор, последствия и ссылки на отчёты. Старую запись помечать заменённой с новым ID. Не переписывать историю так, будто отклонённый вариант никогда не рассматривался.

## Открытые вопросы перед реализацией

### D018 — собственный подписанный обновлятор, 2026-10-20

Уточнение от 2026-10-20 по выбору владельца: автоматические сборка и испытания, ручное одобрение каждой необходимой подписи/публикации. Ключ планируется хранить только в защищённом GitHub Environment `core-release`, доступном задаче `sign-and-publish` из `main` после одобрения `SargeMadovsky`; обход администратором выключен. Окружение настроено; после отдельного явного разрешения владельца от 2026-10-20 ключ загружен в секрет этого окружения. Ежедневная подготовка кандидатов включена, подпись и публикация требуют ручного одобрения. Общий секрет репозитория не создаётся. Причина: сохранить контроль владельца перед выполнением привилегированной части выпуска. Следствия: выпуск ждёт ручного действия, пока его не одобрят; процесс браузера и его расходы не меняются.

Заменяет путь доставки D017 после согласия владельца: независимый Rust-загрузчик/обновлятор с Ed25519, публичный ключ в загрузчике, полные проверенные комплекты CEF + sandbox bootstrap + адаптер. Платный Authenticode не является условием доставки; секретный ключ не включается в поставку. Кнопка и редкий таймер запускают отдельный процесс, постоянной службы нет. Новая версия устанавливается отдельно и выбирается при следующем запуске, откат ограничен подписанным порогом безопасности. Причина: снизить ручное сопровождение без зависимости от сертификата и сохранить sandbox ABI. Следствия: нужны защищённый ключ публикации и автоматические испытания совместимости; экспорт в GitHub Secret требует явного согласия владельца. Ограничения: [ENGINE_UPDATES.md](ENGINE_UPDATES.md). Производительность новой функции обсуждается до реализации и измеряется; нулевая стоимость не обещается.

### D017 — отдельные обновления CEF, 2026-10-19

Уточнение по просьбе владельца изучить ungoogled-chromium: CEF Installer остаётся подготовленным экспериментом. Его требование Authenticode не является общим требованием к безопасным обновлениям. Собственный updater с закреплённым публичным ключом допускается как альтернатива без покупки сертификата, но требует отдельной реализации и приёмки. Ни одна схема не объявлена готовой; источники сравнения и ограничения SignPath внесены в ENGINE_UPDATES.md.

Принято направление по запросу владельца: Windows CEF Installer со stable API и сохранением sandbox. Реализация отделена feature `engine-updates` от переносимого релиза; используется штатный проверяющий загрузчик и официальная цепочка доверия CEF. Не писать собственную замену файлов и не разрешать unsigned fallback в управляемом режиме. Причина: обновление нативного кода требует аутентификации до загрузки и проверки sandbox ABI. Следствие: для включения необходима подпись приложения; совместимые патчи движка могут поставляться отдельно, но новые milestone/ABI потребуют испытаний и иногда нового bootstrap. Полная evergreen-поддержка одной старой оболочки не обещается. Состояние и приёмка: [ENGINE_UPDATES.md](ENGINE_UPDATES.md).

Точная версия CEF/cef-rs; доступность MV2 и нужных сетевых API; UI расширений в минимальной оболочке; фактическая изоляция; цена переноса патчей; ресурсы сборки; лицензирование; канал обновления и ответственность за security fixes.
