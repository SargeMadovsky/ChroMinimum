## Как изменять решения

### D016 — публичная публикация, 2026-10-19

По явному выбору владельца: публичный SargeMadovsky/ChroMinimum, собственный код под MIT. Выпуск — экспериментальный prerelease 0.0.1-alpha.1, без утверждения о завершённой security-приёмке. Локальные отчёты, профили и кеши не публикуются. Linux x64 и macOS ARM64 проходят отдельные сборки и smoke-проверки в GitHub Actions; поддержка не объявляется подтверждённой до фактических результатов.

Новая запись: ID, дата, статус, проблема, варианты, доказательства, выбор, последствия и ссылки на отчёты. Старую запись помечать заменённой с новым ID. Не переписывать историю так, будто отклонённый вариант никогда не рассматривался.

## Открытые вопросы перед реализацией

### D018 — собственный подписанный обновлятор, 2026-10-20

Уточнение от 2026-10-20 по выбору владельца: автоматические сборка и испытания, ручное одобрение каждой необходимой подписи/публикации. Ключ планируется хранить только в защищённом GitHub Environment `core-release`, доступном задаче `sign-and-publish` из `main` после одобрения `SargeMadovsky`; обход администратором выключен. Окружение настроено; после отдельного явного разрешения владельца от 2026-10-20 ключ загружен в секрет этого окружения. Ежедневная подготовка кандидатов включена, подпись и публикация требуют ручного одобрения. Общий секрет репозитория не создаётся. Причина: сохранить контроль владельца перед выполнением привилегированной части выпуска. Следствия: выпуск ждёт ручного действия, пока его не одобрят; процесс браузера и его расходы не меняются.

Заменяет путь доставки D017 после согласия владельца: независимый Rust-загрузчик/обновлятор с Ed25519, публичный ключ в загрузчике, полные проверенные комплекты CEF + sandbox bootstrap + адаптер. Платный Authenticode не является условием доставки; секретный ключ не включается в поставку. Кнопка и редкий таймер запускают отдельный процесс, постоянной службы нет. Новая версия устанавливается отдельно и выбирается при следующем запуске, откат ограничен подписанным порогом безопасности. Причина: снизить ручное сопровождение без зависимости от сертификата и сохранить sandbox ABI. Следствия: нужны защищённый ключ публикации и автоматические испытания совместимости; экспорт в GitHub Secret требует явного согласия владельца. Ограничения: [ENGINE_UPDATES.md](ENGINE_UPDATES.md). Производительность новой функции обсуждается до реализации и измеряется; нулевая стоимость не обещается.

### D017 — отдельные обновления CEF, 2026-10-19

Уточнение по просьбе владельца изучить ungoogled-chromium: CEF Installer остаётся подготовленным экспериментом. Его требование Authenticode не является общим требованием к безопасным обновлениям. Собственный updater с закреплённым публичным ключом допускается как альтернатива без покупки сертификата, но требует отдельной реализации и приёмки. Ни одна схема не объявлена готовой; источники сравнения и ограничения SignPath внесены в ENGINE_UPDATES.md.

Принято направление по запросу владельца: Windows CEF Installer со stable API и сохранением sandbox. Реализация отделена feature `engine-updates` от переносимого релиза; используется штатный проверяющий загрузчик и официальная цепочка доверия CEF. Не писать собственную замену файлов и не разрешать unsigned fallback в управляемом режиме. Причина: обновление нативного кода требует аутентификации до загрузки и проверки sandbox ABI. Следствие: для включения необходима подпись приложения; совместимые патчи движка могут поставляться отдельно, но новые milestone/ABI потребуют испытаний и иногда нового bootstrap. Полная evergreen-поддержка одной старой оболочки не обещается. Состояние и приёмка: [ENGINE_UPDATES.md](ENGINE_UPDATES.md).

Точная версия CEF/cef-rs; доступность MV2 и нужных сетевых API; UI расширений в минимальной оболочке; фактическая изоляция; цена переноса патчей; ресурсы сборки; лицензирование; канал обновления и ответственность за security fixes.
