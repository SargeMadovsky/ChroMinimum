После подтверждения владельцем работы списка подготовлен отдельный
[патч привязки native карточки и отключения flight animation](DOWNLOAD_BUBBLE_ANCHOR.md).

## Текущий вариант — штатный Chrome UI

После ручной проверки владелец показал некорректное собственное окно в тёмной
теме и дублирующую его штатную карточку Chromium. По его предложению собственный
DownloadHandler и окна удалены; сохранение и управление передачами снова
выполняет Chrome runtime CEF. В панели добавлена кнопка «Загрузки» со стрелкой
вниз; она и Ctrl+J открывают `chrome://downloads/` в текущем окне. «Назад»
возвращает сайт. Настройки каталога/запроса сохранения остаются штатными Chrome;
принудительного Save As из предыдущего варианта больше нет. Обработка ссылок
из первого этапа сохранена. Решение: [D037](DECISIONS.md).

Не добавлены зависимости, сетевые запросы оболочки или постоянные службы.
Убраны состояние передач, дополнительные окна и ожидание их уничтожения.
DLL: 872448 → 799744 байта, −72704 (71 КиБ); RAM/CPU/startup не измерены.
Другие файлы runtime не изменены относительно исходного media-кандидата.

`scripts/test-links-downloads.cjs <bootstrap.exe> <new-output> <case>` теперь
проверяет Chrome WebUI: `complete`, `cancel`, `interrupt` или `links`.
Каждый случай использует новый синтетический TEMP-профиль на C: и loopback.
Только в smoke + --test-chrome-downloads специальные заголовки fixture вызывают
настоящие делегаты нативной кнопки и Ctrl+J. Desktop input и computer-use не
используются. CDP Browser.setDownloadBehavior задаёт каталог синтетических
файлов для теста; настройки обычного запуска не меняются.

На финальной DLL прошли три случая, каждый с exit=0 и shutdown_complete:

- `complete1`: 8388608 байт 0x5a, Chrome item.state=2 (Complete).
- `cancel-1`: нажат `#cancel` именно в штатном downloads-item, state=1 (Cancelled).
- `interrupt-1`: сервер оборвал ответ, state=5 (Interrupted).
- В каждом: обычная/target=_blank/gesture window.open ссылки, блокировка popup
  без gesture, отрисованная кнопка с иконкой, её делегат, делегат Ctrl+J,
  одна страница и успешный «Назад» на fixture.

Артефакты: `.local/chrome-downloads-preview-20261025/`, включая result.json,
логи и downloads.png для каждого случая. Снимок через CDP Page.captureScreenshot
просмотрен: штатная тёмная страница и карточка читаемы, старого окна нет.
Это снимок WebUI, а не всей нативной панели. Release, rustfmt, Clippy -D warnings,
Node syntax и diff check прошли. SHA-256 DLL:
`ceeadba226250cd33873326d042a30ba981d3fdcbcb10df0ed87659c909a9028`.

Preview: `.local/chrome-downloads-preview-20261025/Launch.cmd`, отдельный TEMP-
профиль, без CDP и тестовых обработчиков. Основная установка/старый preview/
публичные пакеты не заменялись. Установщик и публикация не выполнялись.

Остаются ручными: реальное нажатие кнопки/Ctrl+J, открытие папки в ОС,
положение всплывающей карточки и летающей анимации у скрытой штатной панели.
Новая кнопка открывает страницу, а не перепривязывает bubble к своим координатам.
Фактические Windows-токены и Linux/macOS этой серией не проверялись; защитные
флаги не менялись. Computer-use запрещён владельцем и не использовался.

## Исторический первый вариант — отдельное окно

Ниже сохранены результаты предыдущей реализации; собственных окон и указанных
ниже test-downloads/native режимов в текущем коде больше нет.

Рабочее дерево, не опубликованный релиз и не обновление основной установки.
Владелец сообщил о неработающей GitHub-ссылке chrominimum.download и выбрал
отдельное окно скачивания в духе IE 5.5/6 вместо страницы chrome://downloads.
Расходы обсуждены до реализации: существующий CEF Views, без новых зависимостей,
таймеров/служб и дополнительных сетевых запросов оболочки; временное окно на файл.

## Поведение

- Явное действие пользователя по HTTP(S)-ссылке, запрашивающей новое окно,
  направляется в текущую страницу через UI task. Обычные переходы сохраняются.
  Незапрошенные popup и прочие схемы через этот путь не открываются.
- CEF DownloadHandler запрашивает штатный «Сохранить как». Затем собственное
  окно показывает путь, источник, процент, полученный объём и скорость.
  При неизвестном размере процент не выдумывается.
- «Отмена» отменяет CEF transfer. При завершении/отмене/ошибке появляется
  «Закрыть»; «Открыть папку» доступна после успешного скачивания.
  Автоматического открытия или выполнения файла нет.
- Закрытие окна во время загрузки отменяет её; закрытие браузера закрывает
  принадлежащие ему окна. CEF message loop заканчивается после уничтожения окон.
- Состояния и UI обновляются событиями CEF. Небольшие записи о закрытых окнах
  остаются в памяти до закрытия браузера, чтобы позднее событие не создало окно
  заново. Собственной постоянной истории и восстановления загрузок нет.

Загрузка новых функций не меняет CEF sandbox, TLS и site isolation.
Обработка popup-форм POST, OAuth с window.opener, внешних протоколов,
множества автоматических скачиваний, восстановления и проверки вредоносных
файлов этой задачей не подтверждается.

## Проверки и границы

`scripts/test-links-downloads.cjs <bootstrap.exe> <new-output> <case>` использует
loopback fixture и новый синтетический TEMP-профиль на C:. Случаи `complete`,
`cancel`, `interrupt`, `links`; режим `native` предназначен для отдельной ручной
приёмки штатного диалога. CDP включается только в smoke + --test-cdp.

В автоматическом режиме --test-downloads сохраняет исключительно в каталог
синтетического smoke-профиля и вызывает тот же делегат кнопки для отмены/закрытия.
Этот режим обходит диалог сохранения, поэтому не доказывает работу настоящего
«Сохранить как», кликов мышью, DPI или внешний вид окна. Обычный запуск не
включает обход, автоматическую отмену или автоматическое закрытие окна.

На принятом Release media CEF (SHA-256 libcef.dll
`ef8d6219fb826b586ca25b60f6583ba0c1453cb9172051521a02f5fb8057e020`):

- Обычная ссылка, target=_blank и gesture window.open достигли назначения
  в одной странице; script popup без gesture не выполнил переход.
- `complete-final`: все 8388608 байт равны 0x5a, окно is_drawn, действие «Закрыть».
- `cancel-final`: вызван делегат отмены, получено canceled, окно закрыто.
- `interrupt-final`: сервер оборвал ответ, получено interrupted, окно закрыто.
- Все три сценария завершились exit=0 и shutdown_complete. Результаты:
  `.local/link-download-release-20261025/`.

Финальные прогоны включают ширину полосы по реальной ширине контейнера,
светлый фон, освобождение строки пути закрытого окна и native-only watchdog.
Release DLL собрана; rustfmt, Clippy -D warnings, Node syntax и git diff check
(с учётом CRLF) прошли. Визуальный вид отдельным GUI-прогоном не подтверждён.
SHA-256 финальной DLL:
`cf5cda758bcd9f0897a6912f82db0fe91ab241a6a8177ce4ae1bcfd4ce703efd`, 872448 байт.
Сравнительные RAM/CPU/startup и размер именно этой функции не измерены;
разницу с архивной DLL нельзя целиком приписывать функции при уже изменённом дереве.

Неудачные прогоны не удалены. Выявлены отсутствие AppContainer RX в новом
каталоге, тайм-ауты профилей на E:, недопустимый пустой делегат CEF Views,
очистка full_path при отмене и аварийное Browser.close через CDP. Runner теперь
использует Page.close; это не доказательство исправления Browser.close в CEF.
На диагностическом CEF чтение UI Automation также вызвало sequence DCHECK.

Computer-use остановлен владельцем через Escape, затем явно запрещён.
Native-приёмка не закончена; тестовый экземпляр native1 остановлен адресно.
Не проверены штатный Save As/его отмена, «Открыть папку», визуальный вид/DPI,
закрытие браузера в середине передачи, Linux/macOS и конкретный переход на
публичном сайте. Прежняя летающая анимация Chromium отдельно не устранена:
её создаёт DownloadToolbarUIController скрытой штатной панели. Сам факт
собственного DownloadHandler не доказывает отключение анимации.

Следующий шаг: ручная проверка preview владельцем, затем завершение приёмки
и отдельная подготовка установщика. Основной установленный браузер и архивный
media-кандидат не заменялись, подпись и публикация не выполнялись.
