# Проверка распространения media CEF — 2026-10-23

## Уточнение 2026-10-24: запрос условий малого тиража

Позднее 2026-10-24 владелец отложил обращение в VIA: сначала приведение сайта
к статусу хобби-проекта, английская версия и рассмотрение альтернатив.
Письмо не отправлено. [Проверка альтернатив из полученного MD](CODEC_ALTERNATIVES_REVIEW_20261024.md).

Проверены текущие первичные страницы Via: [AVC/H.264](https://www.via-la.com/licensing-programs/avc-h-264/)
и [AAC](https://www.via-la.com/licensing-programs/aac/).
Опубликованная таблица AVC для encoder/decoder products указывает $0 per unit
за первые 100000 единиц в год с условиями применения. Это ставка тарифа,
а не подтверждение отсутствия необходимости соглашения/отчётности для CM.
Не переносить этот порог на AAC. В FAQ AAC указано, что PC Software pricing
остаётся доступным для продуктов после одобрения этой категории Via;
конкретная применимость, стоимость и обязательства CM ещё не подтверждены.

Практический следующий шаг: запросить образцы соглашений и условия именно
для бесплатного небольшого браузера, включая определение единицы для загрузок,
повторных установок и обновлений. Личный черновик подготовлен в игнорируемом
.local, сведения издателя в публичную документацию не включены; письмо
не отправлялось. Нулевой per-unit тариф одного пула не подтверждает покрытие
всех возможных прав/территорий или соблюдение LGPL.

Отдельно [FFmpeg checklist](https://www.ffmpeg.org/legal.html) требует внимания
к соответствующим исходникам, сведениям о сборке и уведомлениям. Сам проект
описывает checklist как один из способов выполнения требований, не единственный.
Для монолитной компоновки libcef вопрос relinking остаётся открытым; готовые
локальные source archives сами по себе не закрывают его.

Публичный media-релиз пока не подготовлен к одобрению. Владелец подтвердил,
что отдельных соглашений на H.264/AAC у проекта нет. Это не вывод о незаконности
любого использования или распространения во всех странах; применимость
патентных требований к издателю, территориям и модели распространения не установлена.
Локальная работоспособность и право публичной дистрибуции — разные проверки.

## Установленные факты

Google для CEF с `ffmpeg_branding=Chrome proprietary_codecs=true` прямо указывает
на необходимость соглашений с патентообладателями и соответствующих платежей:
[официальная инструкция](https://support.google.com/webdesigner/answer/10043691?hl=en).
Эти флаги не предоставляют разрешение на патенты; BSD/MIT лицензии оболочки и
CEF этого вопроса не закрывают.

FFmpeg отдельно описывает LGPL, публикацию точного исходного кода, изменений,
сведений о сборке и уведомлений. Их рекомендуемый checklist предполагает
dynamic linking; это не единственный допустимый способ выполнения LGPL.
[FFmpeg legal](https://www.ffmpeg.org/legal.html),
[лицензии FFmpeg](https://ffmpeg.org/doxygen/trunk/md_LICENSE.html).
В данном CEF FFmpeg интегрирован в libcef.dll; отдельной ffmpeg.dll нет.
Необходимо отдельно проверить выполнение условий модификации/перелинковки
в такой компоновке. Один CREDITS.html не подтверждает выполнение всех условий.

Локальные первичные материалы:

- Chromium b859317bf11f6be47f9b7799ec690a0a42a1fb33 / 154.0.8037.98.
- CEF 14c5a089e8452874cb1a556dc3fde26ed2d87723, рабочее дерево чистое.
- FFmpeg a06d51a20a28f980b2ddc6b7d73d69b2d29bf323, рабочее дерево чистое.
- `third_party/ffmpeg/README.chromium`: LGPL-2.1 и permissive лицензии.
- `chromium/config/Chrome/win/x64/config.h`: CONFIG_GPL=0,
  CONFIG_NONFREE=0, CONFIG_VERSION3=0, CONFIG_GPLV3=0.
- Точный COPYING.LGPLv2.1 и CREDITS.chromium включены в архив FFmpeg.
- Полный generated Chromium CREDITS включён в финальный setup; первоначальный
  экспериментальный ZIP содержал sample и не является публичной поставкой.

## Подготовленные материалы

`dist/alpha8-source-materials/` содержит FFmpeg и CEF HEAD archives, snapshot
исходников ChroMinimum, наши патчи, GN args и сведения о сборке; manifest с SHA-256.
Секреты, .git, профили, кеши, инструменты и бинарники в source snapshot не входят.
Архивы остаются локальными. Они не объявляются полным подтверждением LGPL:
все исходники Chromium/его зависимостей отдельно не архивированы; возможность
перелинковки и эквивалентный доступ к необходимым материалам ещё не проверены.
Уведомление и ссылки на исходники на публичной странице/в About также требуют
проверки перед выпуском. Формулировки не добавлены в приложение без завершённого
комплекта и действительной публичной ссылки.

Основной setup и черновик media metadata не подписаны для публичной доставки,
канал не создан. Рабочий ключ и публичный stock workflow не менялись.
Не следует публиковать один unsigned binary и считать исходники по upstream
ссылкам достаточным подтверждением всех обязательств.

## Вариант системных декодеров — только чтение исходников

Дополнение: [отдельный MF-стенд](MEDIA_FOUNDATION_PROBE.md) успешно декодировал
H.264/AAC-LC на Win10 19045 с системными DLL и выключенным DXVA. Это ещё не
интеграция с CEF; карта трёх отдельных путей и ограничения приведены в отчёте.

Автор CEF описал эксперимент с OS decoding и ограничения старых GPU/AAC:
[CEF issue 3559](https://github.com/chromiumembedded/cef/issues/3559).
Это обсуждение M117, его нельзя автоматически переносить на M154.

В нашем M154 `media/filters/win/media_foundation_audio_decoder.cc:GetTypeInfo`
разрешает AAC только при profile=kXHE_AAC и Windows>=WIN11_22H2. Наличие класса
MediaFoundationAudioDecoder не доказывает поддержку AAC-LC. Проверенный AAC-LC
fixture проверен через WebAudio; конкретный backend отдельной трассировкой не
фиксировался. `media/BUILD.gn` также запрещает сочетание
proprietary_codecs=true и ffmpeg_branding=Chromium при media_use_ffmpeg=true.
Следовательно, простая смена GN флага не является проверенным решением.

Следующий технический эксперимент, если выберет владелец: маленький отдельный
стенд Media Foundation для AAC-LC/H.264 на нужной Windows, без полной пересборки
CEF. Только после положительного результата оценивать интеграцию, совместимость
GPU/Windows N и стоимость пересборки. Патентные выводы по OS API тоже требуют
проверки условий; готовая чужая сборка с кодеками автоматически права не передаёт.
