# Исследование модульной поставки CEF

Дата: 2026-10-20. Область: Windows x64, CEF 154.0.34+g14c5a08,
Chromium 154.0.8037.98. Это результаты чтения исходников и измерения файлов,
а не принятое решение о составе продукта или реализованный инсталлятор.

## Локализации

Измерена существующая копия `target/core-final-bundle/core/seed`. Все варианты
сохраняют основной пакет языка и его три дополнительных пакета с суффиксами
FEMININE/MASCULINE/NEUTER. Русский и английский приведены как пример выбора.

| Набор | Файлы | Байты файлов | МиБ | Gzip полезного содержимого, байт |
|---|---:|---:|---:|---:|
| Все языки | 220 | 50 837 436 | 48,48 | 12 834 525 |
| ru + en-US | 8 | 1 794 445 | 1,71 | 462 710 |
| en-US | 4 | 589 666 | 0,56 | 193 634 |

Выбор ru + en-US сокращает языковые файлы на 49 042 991 байт (46,77 МиБ,
96,47% языковых ресурсов). Это не процент всей поставки. Gzip измерен одним
потоком с уровнем 6 и фиксированным mtime; это не размер пакета обновлятора:
заголовки tar, состав и параметры полного архива отличаются.

[README поставки именно этого CEF](https://github.com/chromiumembedded/cef/blob/14c5a089e8452874cb1a556dc3fde26ed2d87723/tools/distrib/win/README.redistrib.txt)
разрешает распространять только настроенные локализации; по умолчанию используется
en-US. При удалении всех языковых ресурсов отдельные веб-компоненты могут
отображаться неверно. Общие resources.pak, ICU и GPU-библиотеки в эксперименте
не удалялись. Выбор языка CEF не переводит собственные строки Rust-оболочки.

Для выборочной загрузки инсталлятором и обновлятором нужны отдельные языковые
пакеты, совместимые с версией ядра. Текущий обновлятор доставляет единый комплект;
отдельная доставка языков пока не реализована.

## Доступность

В [ui/base/ui_features.gni закреплённого Chromium](https://github.com/chromium/chromium/blob/154.0.8037.98/ui/base/ui_features.gni)
есть объявляемый GN-параметр `has_native_accessibility`; на Windows он по
умолчанию true. Следовательно, утверждение «параметра сборки вообще нет» было бы
неверным. Значение false является кандидатом для эксперимента со сборкой,
а не подтверждённым поддерживаемым профилем CEF.

[ui/accessibility/platform/BUILD.gn](https://github.com/chromium/chromium/blob/154.0.8037.98/ui/accessibility/platform/BUILD.gn)
условно включает часть платформенных реализаций, в том числе Windows UIA и
IAccessible2. При этом общий код остаётся в
[ui/accessibility/BUILD.gn](https://github.com/chromium/chromium/blob/154.0.8037.98/ui/accessibility/BUILD.gn),
а Blink имеет собственный
[модуль доступности](https://github.com/chromium/chromium/blob/154.0.8037.98/third_party/blink/renderer/modules/accessibility/BUILD.gn).
Параметр не означает удаления всей доступности и не создаёт устанавливаемого плагина.
Готовая поставка не содержит отдельного пакета, удалением которого можно вырезать
эти части из libcef.dll. Цель GN component сама по себе не означает съёмную DLL
в поставке CEF.

В локальном `include/cef_browser.h` имеется SetAccessibilityState с состояниями
DEFAULT/ENABLED/DISABLED и описанием runtime-переключателей. Управление выполнением
не уменьшает размер уже собранной DLL. В приложении также используются accessible
names нативных кнопок; последствия исключения платформенной поддержки для CEF Views
потребуют проверки. Совместимость расширений от такого изменения не доказана.

Полная генерация GN, сборка CEF с false и runtime-проверка не выполнялись. Размер,
запуск, RAM и CPU такого варианта неизвестны. Дополнительных постоянных процессов
исследование не добавляет. Следующий этап для доступности — отдельная сборочная
проверка с сохранением sandbox, PDF и инфраструктуры расширений, затем сравнение
с тем же исходным профилем сборки.

## Неуспешные запуски и ограничение среды

Скрипт `scripts/audit-cef-locales.py` измеряет файлы и опционально создаёт новую
копию с ru/en-US и отдельным тестовым профилем. SHA-256 исходной и скопированной
libcef.dll совпал:
`e3da6707a840a8f33f565e011542169fd51aaa5218603eb7a89039fb16d79ae7`.

Две попытки из ограниченной среды агента создали браузер и панель, но завершились
кодом 2147483651 (0x80000003), без успешной загрузки fixture и штатного shutdown.
Первая использовала file URL, вторая — временный сервер только на 127.0.0.1.
Журналы обеих содержат повторные падения GPU-процесса с -1073741515 (0xC0000135);
во второй явно записано FATAL `GPU process isn't usable. Goodbye.`
Коды Windows: [Microsoft NTSTATUS](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-erref/596a1078-e883-4972-9bbc-49e60bebca55).
Недоступная DLL не установлена; связь с ограниченной средой вероятна с учётом
ранее записанного аналогичного сбоя Chrome в BENCHMARKS.md, но контрольного запуска
того же комплекта вне ограничений в этом исследовании нет.

Пользователь сообщил о повторяющемся окне с 0x80000003. После сообщения новые
запуски прекращены; список процессов chrominimum при заключительной проверке пуст.
Ошибка не исправлена. Связь с сокращением локализаций не доказана. Следующий
runtime-тест должен сравнить полный и сокращённый набор в обычном интерактивном
сеансе с одинаковыми бинарниками, свежими тестовыми профилями и сохранённой защитой.
Выбор ru через CefSettings.locale, PDF, отображение шрифтов и доступность не проверены.

Локальные машинные результаты: `.local/cef-modularity-2026-10-20/audit.json` и
`.local/cef-modularity-2026-10-20-http/audit.json`; журналы находятся рядом в test-data.
Для повторения только измерений без запуска:

```powershell
python scripts/audit-cef-locales.py --bundle target/core-final-bundle/core/seed --output .local/cef-locale-audit-new
```

Флаг --smoke запускает настоящее окно; из ограниченной среды агента его не применять.

## Контроль вне ограниченной среды

После команды владельца продолжить выполнены два запуска через разрешённое
исполнение вне ограниченной среды агента. Защита самого браузера не отключалась.
Использованы новые копии и свежие тестовые профили, локальный HTTP fixture.

| Набор | Код завершения | HTML/JavaScript | Закрытие и shutdown |
|---|---:|---|---|
| Все 220 языковых файлов | 0 | HTTP 200, fixture_javascript_ok | Пройдены |
| ru + en-US, 8 файлов | 0 | HTTP 200, fixture_javascript_ok | Пройдены |

SHA-256 всех 19 файлов верхнего уровня двух тестовых комплектов совпали; различался
только состав locales. После завершения процессов chrominimum не осталось.
В обоих журналах нет прежнего FATAL о недоступном GPU-процессе; присутствует
сообщение AMD VideoProcessorGetOutputExtension с 0x80004005, не помешавшее этому
сценарию. Нельзя считать это проверкой аппаратного декодирования видео.

Это подтверждает прохождение узкого smoke со сокращёнными языками и указывает
на зависимость прежнего GPU-сбоя от среды запуска. Точная недоступная DLL не
установлена, исправление CEF/драйвера не выполнялось. Нельзя переносить этот вывод
на все сообщённые пользователем падения без их журналов.

Машинные результаты находятся в `.local/cef-modularity-unrestricted-full/audit.json`
и `.local/cef-modularity-unrestricted-en-ru/audit.json`.
Для контрольного полного набора к команде аудита добавлены `--locale-set all --smoke`;
по умолчанию smoke использует ru+en-US. Этот эксперимент использует язык CEF по
умолчанию en-US и не проверяет переключение на ru, PDF, визуальное отображение
иностранных шрифтов или экранный диктор. Размеры подтверждены, ускорение и экономия
памяти/CPU не измерялись. Следующий ограниченный этап — явный выбор локализации
CEF и проверка локализуемых элементов перед изменением упаковки.

## Явный выбор языка CEF

В отдельную Release-сборку адаптера добавлен исследовательский параметр
`--test-cef-locale=ru` или `--test-cef-locale=en-US`. Он действует только с
`--smoke-test`, допускает лишь эти два значения и задаёт `CefSettings.locale`.
В обычном запуске поведение не меняется. Перевод оболочки, настройки установки
и изменение пакетов обновлятора этим не реализованы.

Обе копии содержали только 8 языковых файлов ru/en-US и один и тот же новый
адаптер. Выполнены реальные запуски вне ограниченной среды, с отдельными свежими
профилями. Локальная страница содержала обязательное пустое поле ввода; его
`validationMessage` генерируется движком, а не текстом fixture. Результат
передавался POST-запросом временному серверу на 127.0.0.1.

| Язык CEF | validationMessage | navigator.language | Результат |
|---|---|---|---|
| ru | Заполните это поле. | ru-RU | Пройден |
| en-US | Please fill out this field. | en-US | Пройден |

Оба запуска: HTTP 200, успешный JavaScript, штатные browser_closed и
shutdown_complete, exit code 0; после завершения процессов chrominimum нет.
Сам CEF не пересобирался, sandbox не отключался. Прочитан комментарий locale
в локальном `include/internal/cef_types.h` закреплённого CEF: на Linux этот
параметр игнорируется в пользу переменных среды, поэтому вывод относится к Windows.

Проверки изменений: Release-сборка DLL, clippy с запретом предупреждений,
rustfmt, синтаксис Python, git diff --check и ручное ревью ограничений тестового
параметра. Машинные результаты: `.local/cef-explicit-locale-ru/audit.json` и
`.local/cef-explicit-locale-en/audit.json`.

Повторение после сборки `target/release/chrominimum.dll` (новый каталог output
для каждого запуска, только вне ограниченной среды агента):

```powershell
python scripts/audit-cef-locales.py --bundle target/core-final-bundle/core/seed --output .local/cef-ru-new --adapter target/release/chrominimum.dll --test-cef-locale ru --smoke
python scripts/audit-cef-locales.py --bundle target/core-final-bundle/core/seed --output .local/cef-en-new --adapter target/release/chrominimum.dll --test-cef-locale en-US --smoke
```

Теперь подтверждены выбор языка CEF и локализованное сообщение в проверенном
сценарии. Визуальный popup валидации, меню, PDF, все прочие строки движка,
перевод кнопок оболочки, отсутствующий выбранный язык, смена языка существующего
профиля и выборочные обновления ещё не проверены. Экономия 46,77 МиБ относится
к языковым файлам; производительность не измерялась.

Следующий этап для инсталлятора — сохраняемая конфигурация выбранных компонентов
и правила поставки языков, затем их проверка вместе с обновлятором. Доступность
остаётся отдельным исследованием сборки, не готовым опциональным пакетом.
