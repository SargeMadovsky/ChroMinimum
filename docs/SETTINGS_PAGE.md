# Страница настроек ChroMinimum

Статус: первая версия реализована 2026-11-22 (D046), прошла
`scripts/test-settings.cjs`. Ниже — исходный проект с ответами владельца.
Затраты в таблице — **оценки**, замеры — в разделе «Реализация»
([performance.mdc](../.cursor/rules/performance.mdc)).

## Зачем

Сейчас пункт меню «Настройки» открывает `chrome://settings/` в текущей
странице. В нём смешаны полезные настройки движка (пароли, данные сайтов,
загрузки, языки) и неприменимые к ChroMinimum (аккаунт Google, синхронизация,
браузер по умолчанию, запуск). Собственные настройки CM разбросаны:
«Ускорять первый запуск» — флажок в меню, обновления ядра — пункт меню,
состояние окна — скрытый файл. Новым функциям (поиск из адресной строки,
алиасы, сессия, Boss Key — см. [MAXTHON3_FEATURES.md](MAXTHON3_FEATURES.md))
нужно одно место.

## Принцип разделения

Одна страница `chrominimum://settings/`, два явно подписанных раздела.

**1. ChroMinimum** — настройки оболочки. Хранит и применяет CM, движок о них
не знает.

| Группа | Настройки | Есть сейчас |
|---|---|---|
| Запуск | Ускорять первый запуск после входа в Windows (D045) | да, флажок в меню |
| Обновления ядра | Состояние, «Проверить сейчас» | да, пункт меню |
| Адресная строка | Поисковый провайдер, алиасы | нет, следующие задачи |
| Окно | Запоминать размер и положение | да, без выключателя |
| О программе | Версии CM и CEF, ссылки | да, отдельное окно |

В первой версии только то, что уже есть. Новые группы появляются вместе со
своими функциями. Пустых заглушек нет.

**2. Движок Chromium** — ничего не хранит сам. Это список ссылок на нужные
разделы `chrome://settings` с подписью «Эти настройки хранит движок
Chromium». Кандидаты:

| Ссылка | Адрес (проверить в CEF 154) |
|---|---|
| Пароли | `chrome://password-manager/passwords` |
| Данные сайтов и разрешения | `chrome://settings/content` |
| Удалить данные о просмотре | `chrome://settings/clearBrowserData` |
| Конфиденциальность и безопасность | `chrome://settings/privacy` |
| Загрузки | `chrome://settings/downloads` |
| Языки и правописание | `chrome://settings/languages` |
| Шрифты и масштаб | `chrome://settings/fonts`, `chrome://settings/appearance` |
| Сертификаты | `chrome://certificate-manager/` |

Ссылку на раздел, который в CEF не работает или ведёт к аккаунту или
синхронизации, не показывать. Каждую ссылку проверяет тест.

Позже, отдельно: блок только для чтения «Что ChroMinimum меняет в движке»
(отключённые фоновые службы, сетевая песочница и т. п.). Он делает
отличия от Chrome видимыми, но требует сначала составить этот список.

## Как показывать

Рекомендация: **отдельное окно настроек**, как окно параметров Maxthon.
Пока нет вкладок, открытие настроек в текущей странице теряет сайт
пользователя (формы, прокрутку). Ссылки раздела «Движок» открываются в том же
окне настроек; «Назад» возвращает к странице CM. Повторное «Настройки» при
открытом окне выводит его на передний план, второе окно не создаётся.

Альтернатива — текущая страница, как сейчас `chrome://settings`. Дешевле
(нет второго окна), но с той же потерей страницы.

## Механизм

- Своя схема `chrominimum` регистрируется как standard + secure, без CORS и
  fetch с других схем. Страница (HTML/CSS/JS, ~15–30 КБ) встроена в DLL;
  отдаёт её обработчик схемы в процессе браузера. Сеть и файлы с диска не
  используются.
- Запись настроек — POST-запрос страницы к `chrominimum://settings/api/…`.
  Обработчик в процессе браузера проверяет: запрос пришёл из главного фрейма
  окна настроек с источником `chrominimum://settings`; ключ из белого списка;
  значение корректно. Иначе — отказ. Так проверка разрешений остаётся на
  стороне получателя (AGENTS.md).
- Веб-страницы не могут перейти на `chrominimum://`. `on_before_browse`
  разрешает такой адрес только из меню и ввода пользователя.
- Хранение: один текстовый файл `key=value` в каталоге данных приложения,
  рядом с состоянием окна. Свой строгий разбор и тесты, как у `window_state`.
  Атомарная запись (временный файл + переименование). Без serde и других
  новых зависимостей. Читается один раз при старте; это единицы КБ.
- Флажок «Ускорять первый запуск» остаётся в реестре, как в D045. Страница
  читает и меняет его через существующий `login_prewarm`, второго хранилища нет.

**Главная техническая цена.** Схема регистрируется во всех процессах
(`on_register_custom_schemes`), значит дочерние процессы должны получать
объект App. Сейчас `execute_process` в подпроцессах вызывается с `None`
(Windows — `run()` в `src/lib.rs`, macOS — `src/bin/helper.rs`). Это
изменение запуска renderer, GPU и utility-процессов. После него повторно
проверить sandbox, сетевую песочницу, smoke и время старта. cef-rs (rev
163744c) поддерживает `register_scheme_handler_factory` и
`on_register_custom_schemes`; в его примерах это используется.

Запасной вариант без изменения подпроцессов — обработчик для
`https://settings.chrominimum.invalid/`. Отклонён: адрес выглядит как
настоящий сайт, получает индикатор HTTPS, cookies и хранилище веб-источника.

## Затраты (оценка)

| Ресурс | Ожидание |
|---|---|
| Запуск | Регистрация схемы и чтение маленького файла — микросекунды; изменение App в подпроцессах — замерить |
| Память | 0, пока окно закрыто. Открытое окно — ещё один renderer, порядок 30–60 МБ (замерить); освобождается при закрытии |
| CPU | Нет фоновой работы, таймеров и опроса |
| Размер | Страница 15–30 КБ + код ~20–40 КБ в DLL |
| Фон | Нет |
| Сеть | Нет. `chrome://` — локальные страницы движка |

## Первая версия

1. Схема, обработчик, встроенная страница, окно настроек, пункт меню
   «Настройки» ведёт туда.
2. Раздел ChroMinimum: перенести «Ускорять первый запуск» и обновления ядра.
   Из меню флажок убрать, пункт обновлений оставить для быстрого доступа.
3. Раздел «Движок»: только ссылки, прошедшие проверку в CEF 154.
4. Тесты: разбор файла настроек; отказ API для чужого фрейма и источника и
   для неизвестного ключа; запрет перехода веб-страницы на `chrominimum://`;
   каждая ссылка «Движка» открывается. Затем smoke, sandbox и замер старта до
   и после.

Не входит: поиск и алиасы (отдельные задачи; они добавят свою группу),
локализация en (страница сразу пишется с выносом строк, но перевод отдельно),
тёмная тема страницы (только `prefers-color-scheme` в CSS, без настройки).

## Ответы владельца

1. Отдельное окно настроек.
2. Флажок «Ускорять первый запуск» — только в настройках, по умолчанию
   выключен; из меню убран.
3. Пункт меню «Удалить данные о просмотре…» — стандартный из CEF, оставить
   как есть.

## Реализация (первая версия)

- Код: `src/settings_page.rs`, страница `src/settings_page/` (index.html,
  settings.css, settings.js — 8,0 КБ всего). Отличия от проекта:
  - файла настроек `key=value` нет: обе настройки первой версии уже имеют
    своё хранилище (реестр и состояние обновлений);
  - вызывающего API проверяют по инициатору запроса, а не по URL фрейма:
    при первой загрузке URL фрейма ещё прежний (подробности в D046).
- Окно 860×680 по центру основного монитора; одно на процесс. Пункт меню
  «Настройки» и ввод `chrominimum://settings` открывают его или выводят вперёд.
- Раздел «Движок»: все 9 ссылок таблицы открываются в CEF 154, «Назад»
  возвращает на страницу CM. Сами страницы `chrome://` по-английски — так
  движок ведёт себя и без CM; это отдельный вопрос языка интерфейса.
- `scripts/test-settings.cjs` проверяет на одноразовом профиле:
  - окно из меню и из адресной строки; второе окно не создаётся;
  - состояние страницы, CSP (inline-скрипт блокируется), тёмную тему;
  - правила API (GET, неизвестный путь, неверный ключ дают 404);
  - переключатель прогрева на тестовом ключе реестра; настоящий Run не меняется;
  - показ статуса обновления событием;
  - веб-страница не может открыть, встроить или вызвать `chrominimum://`;
  - веб-ссылка из окна настроек уходит в обычное окно;
  - все ссылки движка; из `chrome://` в окне настроек API недоступен.
- Отказы `fetch` веб-страниц и `chrome://` к `chrominimum://` срабатывают
  уже в Chromium (схема DISPLAY_ISOLATED, без CORS). До проверок процесса
  браузера такие запросы не доходят: те остаются вторым рубежом.
- Не проверено: macOS/Linux (код собран только для Windows), экранный диктор,
  настоящий вход в Windows с включённым прогревом.
