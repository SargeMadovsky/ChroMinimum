Частный локальный тестовый комплект CM / UC / Chrome, 2026-10-24

Не публиковать этот комплект. Это копии существующих тестовых сборок,
не новые установщики и не публичный выпуск браузеров.

1. Создайте обычного локального пользователя Windows без аккаунта Microsoft.
2. Перезагрузите ПК и войдите в нового пользователя; основной сеанс должен
   быть завершён. Дождитесь окончания первоначальной настройки Windows.
3. Не устанавливайте браузеры, не импортируйте данные и не входите в аккаунты.
   Всё необходимое, включая Node.js, находится здесь. Интернет для самих
   тестовых страниц не требуется; системные/браузерные службы могут работать.
4. В терминале из этого каталога выполните START.cmd --preflight-only.
   Эта команда проверяет файлы и сохраняет окружение, браузеры не запускает.
5. Для короткого проверочного круга: START.cmd --pilot (около 10 минут).
   Для серии: START.cmd --suite, либо двойной щелчок START.cmd
   (около 40 минут: по 5 кругов видео/игры и 1 круг WebRTC).
6. Не пользуйтесь ПК, не переключайте и не сворачивайте окна. Видимая область
   теста 1000x600, масштаб Windows/браузера должен давать DPR=1 и scale=1.
   Не меняйте Defender, firewall, sandbox, сертификаты, GPU-защиту, драйвер
   или частоту экрана. Игровая сводка использует reference 165 Hz текущего ПК.

START.cmd использует только tools/node.exe. Установка Node.js не нужна.
Каждая попытка создаёт новый тестовый профиль в TEMP текущего пользователя.
Никакие существующие профили не открываются и не закрываются.
Зависшие тестовые процессы не завершаются принудительно; при неудаче
штатного закрытия серия останавливается и сохраняет ошибку.

Общий отчёт: suite-reports/<UTC timestamp>/suite.json.
Сырые прогоны: .local/comparison-runs/<UTC timestamp>/.
Файлы неудачных попыток сохраняются, автоматических повторов нет.
Закрытие терминала/выход из Windows прервёт серию; незавершённый отчёт
не считается успешным. После тестов вернитесь в основной профиль и сообщите
путь последнего suite.json. Пароли, cookies и реальные звонки не нужны.

Ограничения: это синтетическое видео, инструментированный поворот камеры
в three.js и локальная пара WebRTC. Не проверяются реальные камера/микрофон,
интернет/NAT/TURN, качество физического вывода звука и display presentation.
CPU, private bytes, GPU load и чистая цена инструментирования не измеряются.
Внешние размеры окон различаются; измеряемый iframe одинаков.
Версии Chromium различаются, сравниваются продукты целиком, а не только оболочки.

В UC ранее не было ICE-кандидатов в локальном WebRTC без STUN/TURN.
Этот отказ сохраняется как результат; настройки UC ради прохождения не меняются.
Поэтому итоговый код 1 и allStagesAccepted=false могут быть ожидаемы даже
при полном завершении серии. Проверяйте completed и причины в сырых отчётах.
Отказ UC здесь не доказывает отказ реальной конференции с TURN.
У Chrome ранее отклонялись попытки с потерей фокуса.
Наличие RTP-пакетов само по себе не принимается за ненулевой звук:
WebRTC проверяет декодированный PCM отдельным TrackProcessor.

Полученные числа не являются автоматическим доказательством превосходства
браузера. Публиковать выводы можно только после проверки всех попыток,
условий и ограничений. Этот комплект не меняет установленный ChroMinimum.
readyForFinalSuite=false в сырых отчётах обозначает ограничения полной
продуктовой приёмки; комплект готов для описанной локальной контрольной серии.
