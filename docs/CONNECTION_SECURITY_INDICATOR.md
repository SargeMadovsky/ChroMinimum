# Индикатор соединения — 2 ноября 2026

Актуальная реализация панели заменена штатным Chromium PageInfo: см.
[NATIVE_SSL_PANEL](NATIVE_SSL_PANEL.md). Ниже сохранена история собственных прототипов.

По запросу владельца эта задача выполняется перед сквозной проверкой обновлений.
Добавлен небольшой native индикатор слева от поля адреса. Зелёный замок означает
подтверждённое TLS-соединение и проверенный Chromium сертификат, а не безопасность
содержимого сайта. HTTP показывает предупреждение, ошибка сертификата — красный
знак; локальные/внутренние страницы и неподтверждённое состояние имеют нейтральный
знак. Tooltip и accessible name поясняют состояние. По последующему запросу
владельца добавлена native панель по нажатию (см. дополнение ниже).
Просмотр полей сертификата в эту задачу не входит.

## Источник состояния

Используется pinned cef-rs из Cargo.toml: BrowserHost.visible_navigation_entry,
NavigationEntry.sslstatus, IsSecureConnection, X509Certificate и штатный
is_cert_status_error. Информационные cert-status биты не считаются ошибками.
[Первичный API CEF 154](https://cef-builds.spotifycdn.com/docs/154.0/classCefSSLStatus.html).
Один HTTPS URL не даёт зелёного замка. Обнаруженное CEF небезопасное содержимое
также запрещает зелёное состояние.

Перед main-frame навигацией подтверждение сбрасывается; до commit используется
неподтверждённое состояние. После commit, событий загрузки и изменения адреса
читается visible entry. Ошибка main-frame загрузки сохраняется до следующей
навигации; ERR_ABORTED не объявляется ошибкой сертификата. Subframe ошибки
не подменяют состояние главной страницы. Проверка сертификатов, sandbox и
обработка error page Chromium не изменены.

Это индикатор сертификата/соединения, не полная копия Chromium SecurityState:
немедленное обнаружение динамического mixed content после завершения всех
событий загрузки не доказано. Отдельного callback смены security state в
использованном публичном DisplayHandler нет; таймер опроса не добавлялся.

## Проверки

- Release с windows-platform-codecs, Clippy с -D warnings, rustfmt, diff check.
- 16 Rust-тестов, включая все сочетания условий выдачи зелёного замка.
- scripts/test-connection-security.cjs: HTTP, HTTPS, file, HTTP→HTTPS redirect,
  недоверенный TLS, восстановление HTTPS после ошибки и HTTPS→HTTP — 7 случаев.
  Проверены сброс предыдущего подтверждения, код выхода 0 и shutdown_complete.
  Недоверенный TLS не получил ни одного HTTP-запроса. Профиль одноразовый в TEMP.
- Отдельная проверка PDF и фактических токенов: renderer restricted/Untrusted,
  NetworkService Low/AppContainer, штатное завершение.

Первый запуск внутри ограниченной среды агента отказал по network sandbox;
повтор вне неё прошёл без изменения защиты браузера. Общий прежний security
runner на профиле E: подтвердил отказ сертификату, но последующий HTTPS не успел
дать main_frame_loaded до watchdog. Этот проход целиком не принят. Успешная
7-case серия использует новый TEMP-профиль; изменение диска не объявляется

Ранние варианты нового стенда использовали CDP Browser.close и получали
0x80000003 после browser_closed. Переход на Page.close, как в существующих
принятых стендах, дал штатное завершение. Причина отказа Browser.close не доказана.
Остановленные прогоны сохранены в .local/connection-security-20261102.
Визуальная/DPI/live-theme приёмка владельцем ещё не выполнена; CDP screenshot
страницы не считается проверкой native панели.

## Расходы и кандидат

Новых зависимостей, процессов, служб, таймеров и сетевых запросов индикатора нет.
CEF DLL/ресурсы не пересобирались. Обновление — по событиям, перерисовка при смене
состояния/темы. Native элемент занимает минимум 28×32 плюс существующий зазор 6px;
поле URL остаётся растягиваемым. Адаптер 849920→861184 байта (+11264 байта).
Это разница двух конкретных DLL, не измерение памяти. Startup/CPU/RAM и размер
сжатого установщика не измерены.

Отдельный кандидат: .local/connection-security-20261102/Launch.cmd.
Он открывает example.com с отдельным TestProfile в TEMP. Основная установка,
рабочий профиль и публичная alpha.8 не заменялись. Новый setup/seed пока не собран;
обновление только ядра не доставляет изменённую DLL адаптера.
Следующий шаг — визуальная приёмка индикатора, затем согласованная проверка
обновлений; перед поставкой нового адаптера нужна полная установка/seed-приёмка.

## Панель по нажатию — последующее уточнение 2 ноября

Владелец согласовал native панель, похожую по устройству на предоставленный
пример: значок, заголовок состояния, короткое объяснение и крестик. Реализация
в src/security_panel.rs использует CefWindow.AddOverlayView, а не HTML/DOM.
Все тексты — фиксированные строки браузера, состояние читается из того же
CEF SSLStatus. Само наличие сертификата не считается успешной проверкой.
Панель не содержит разрешения обхода ошибок, не меняет trust store и TLS callbacks.

Панель создаётся только при открытии, располагается под индикатором, получает
native фокус. Закрывается повторным нажатием, крестиком, Escape, при навигации,
смене security state, изменении размеров окна/fullscreen, деактивации окна,
фокусировке поля адреса или возврате фокуса странице. Переходы не оставляют
старое подтверждение поверх нового сайта. Это собственная панель ChroMinimum,
не штатный PageInfo Chromium и не просмотрщик подробностей X509.

Новый кандидат: .local/connection-security-panel-20261102/Launch.cmd,
отдельный синтетический TestProfile в TEMP. Публичная поставка и основная
установка не менялись. Панель 440×146 DIP; ширина ограничивается окном.
DLL 878080 байт: +16896 относительно варианта только с индикатором,
+28160 относительно опубликованного адаптера. Процессы/службы/таймеры/сеть
не добавлены; startup/CPU/RAM/сжатый setup не измерялись.

Release/Clippy и 16 Rust tests прошли. Расширенный test-connection-security.cjs
прошёл 7 состояний/переходов: для каждого проверены совпадение состояния панели,
is_drawn=1, геометрия, callback закрытия и повторное открытие. Навигация убирает
предыдущую панель; выход с открытой панелью — exit0/shutdown_complete. При плохом
сертификате сервер получил 0 HTTP-запросов. Тестовые title-команды доступны
только при --smoke-test + --test-security-panel; обычная страница не получает API
управления native панелью. Стенд вызывает настоящие callbacks, но не эмулирует
физическую мышь. Escape, физические клики, живое переключение темы и DPI пока
не считаются визуально принятыми.

Два первых запуска не завершили начальную HTTP загрузку/подготовку CDP;
последующие полный и финальный прогоны прошли. Причина стартовых задержек
не доказана; увеличены только диагностические ожидания. Неуспехи сохранены.
[Финальный отчёт панели](reports/connection-security-panel-20261102/transitions-final/result.json).

## Отзыв владельца и исправление закрытия

Владелец подтвердил открытие панели, но сообщил о закрытии браузера при настоящем
клике по крестику. Позже уточнил: клик снаружи нормально скрывает панель.
Это подтверждает различие native event paths; прежние callback-тесты не заменяют
нажатие мышью. В исходном варианте общий dismiss синхронно вызывал Destroy,
в том числе из callback кнопки, принадлежащей уничтожаемой панели. При клике
снаружи обработчик события находится в другом view. Точная причина завершения
без crash trace не доказана; синхронное разрушение активной иерархии устранено.

Теперь общий путь крестика/наружного фокуса сначала скрывает overlay, затем
передаёт его уничтожение в следующую UI task. Навигация/смена состояния используют
тот же путь. TLS и CEF ядро не менялись. Release/Clippy,16 Rust tests и7-case
серия прошли; тест теперь ждёт отложенного уничтожения и проверяет, что браузер
продолжает выполнять JS после callback крестика. Физический клик ещё не повторён.
DLL879104байта, +1024 к предыдущей панели; startup/CPU/RAM не измерялись.

Кандидат: .local/connection-security-panel-closefix-20261102/Launch.cmd.
[Отчёт](reports/connection-security-panel-closefix-20261102/summary.json).
Внешний вид в этом ограниченном исправлении не менялся. Для последующей замены
самодельной панели изучены pinned PageInfoBubbleView/BubbleDialogDelegateView
Chromium: это внутренние C++ компоненты, не готовый публичный Views API CEF.
Их использование из нашей панели потребует отдельной интеграции и пересборки
CEF; она не запускалась. Новых служб/сети для этого не ожидается, стоимость
пересборки и изменения размера/старта/памяти пока не определена.

## Фокус крестика и оформление по образцу загрузок

Владелец подтвердил closefix («теперь всё ок»). Синяя обводка исходила от
принудительного close.request_focus при открытии. Теперь фокус получает native
контейнер, а крестик остаётся доступным через Tab со штатной рамкой фокуса.
Глобальное отключение индикации клавиатурного фокуса не применяется.
Release/Clippy и7-case серия прошли: при каждом открытии panel.has_focus=1,
close.has_focus=0; закрытие/повтор/навигация/TLS/shutdown сохранены.
Физические Tab и внешний вид ещё не приняты. DLL879616байт (+512 к closefix),
startup/CPU/RAM не измерялись; сеть/процессы/зависимости не добавлены.

Кандидат: .local/connection-security-panel-focusfix-20261102/Launch.cmd.
[Сводка](reports/connection-security-panel-focusfix-20261102/summary.json).

Владелец предложил оформление как у мини-панели загрузок. Проверен pinned
download_toolbar_ui_controller.cc: контейнер — views::BubbleDialogDelegate,
параметры оформления берутся из ChromeLayoutProvider. Это подходящий образец
для единого native оформления, но не готовый стиль публичного CefPanel.
Вариант: использовать тот же Chromium bubble-контейнер для сведений о соединении
через ограниченную C++ интеграцию. Тень/скругления/отступы/кнопка закрытия должны
приходить от штатного компонента. Согласованная TLS-проверка остаётся в CEF.
Это направление исследования, не реализованный дизайн. Пересборка ядра не
запускалась. Ожидаются CPU/дисковые расходы сборки/перелинковки; новых служб или
сетевых функций приложения не требуется. Runtime CPU/память/запуск/размер пока
не измерены, точная стоимость сборки ещё не оценена.
