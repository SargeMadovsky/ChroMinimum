## Закреплённые исходники

[source-build.json](../patches/chromium/source-build.json) фиксирует CEF
14c5a089e8452874cb1a556dc3fde26ed2d87723, ветку 8037, Chromium 154.0.8037.98,
depot_tools и SHA-256 upstream automate-git.py. Совместимость Chromium прочитана
из CHROMIUM_BUILD_COMPATIBILITY.txt именно этого CEF commit. Инструменты:
Build Tools 2026 18.11.1, C++/ATL/MFC, SDK/Debugging Tools 28000.2270.

[Upstream CEF build instructions](https://chromiumembedded.github.io/cef/branches_and_building)
и закреплённый [automate-git.py](https://github.com/chromiumembedded/cef/blob/14c5a089e8452874cb1a556dc3fde26ed2d87723/tools/automate/automate-git.py)
используются для получения исходников и зависимостей. История Chromium не
загружается. Глобальный PATH не меняется; usage metrics локального depot_tools
отключены. Checkout/build потребуют значительного диска, CPU и времени;
полные затраты пока не измерены. На ПК обнаружены 32 GiB RAM и 16 логических CPU.

## Команды

Из корня проекта, в обычной среде Windows с доступом к сети и запуску инструментов:

```powershell
./scripts/build-cef.ps1 -BuildRoot "$env:TEMP/cm-cef154" -Stage Download
./scripts/build-cef.ps1 -BuildRoot "$env:TEMP/cm-cef154" -Stage Build -Jobs 8
```

Параметр `-Python` позволяет явно выбрать рабочий Python 3. Для начального
локального запуска использовался Python из runtime Codex. Каталог build root
должен быть отдельным, без пробелов; текущий расположен на C:, проект на E: HDD.

`Download` использует upstream automation без компиляции/упаковки.
`Build` проверяет CEF commit, выбирает только Release_GN_x64, применяет наш патч,
генерирует конфигурацию CEF, повторно проверяет патч и собирает libcef/bootstrap.
Это первая проверочная конфигурация: is_official_build=false,
is_component_build=false, symbol_level=1, chrome_pgo_phase=0. Она не является
готовой конфигурацией выпуска; производительность относительно stock не измерена.
Автопубликация, подпись и установка этой командой не выполняются.

## Обязательность патча и обновления

[apply-cef-patches.py](../scripts/apply-cef-patches.py) проверяет версию Chromium
и SHA-256 исходного файла с нормализованными LF. Применение допускается только
к известному исходнику; повторное применение к известному результату безопасно.
Другой исходник или версия завершают подготовку ошибкой. На копиях проверены:
первое/повторное применение, отказ на изменённом файле и другой версии.

Патч требует AvoidAutoTriggerListAccountsOnStale в оболочке только вместе с
исправленным CEF. В текущей stock-сборке оболочки этот флаг не включён.
Состояние source_patch_applied_not_build_validation не подтверждает успешную
компиляцию, отсутствие запросов или исправность авторизации.

Пользовательский обновлятор должен получать уже собранное и проверенное ядро.
На ПК пользователя исходники не компилируются. При переходе на другой CEF
потребуется пересмотреть/перезакрепить патч и повторить приёмку.

**Текущий core-update.yml всё ещё скачивает upstream бинарники через fetch-core.py.**
Его перевод на собственное ядро пока не выполнен. Применение патча ко всем
выпускаемым обновлениям ещё не обеспечено. Перед выпуском собственного ядра
обязательны доставка всего согласованного runtime/bootstrap, новая идентичность
пакета и baseline/security sequence, проверка adapter, подписи и отсутствие
возможности возврата на stock через канал обновлений. Проверки существующего
обновлятора нельзя обходить ради запуска.

### Возобновление после блокировки Defender

Windows заблокировала CIPD instance
`NuXBEfKu8082d55WUbs6_3P0puTPCI4A1Df4BnQ1Z40C` пакета
`chromium/third_party/updater/chrome_win_x86` при получении/распаковке.
Пользователь подтвердил то же срабатывание для .cipd/tmp/dl_36821605.
Тестовый updater EXE не запускался; заключение о ложном срабатывании не делалось.

В закреплённых исходниках third_party/updater/BUILD.gn цель old_updater
помечена testonly=true. Windows-файлы UpdaterSetup_test.exe также перечислены
как data тестов chrome/updater/BUILD.gn. Для libcef/bootstrap эти тестовые
пакеты не требуются. Попытка custom_deps=None оказалась недостаточной для CIPD:
повторный ensure снова прочитал заблокированный пакет, загрузка остановлена.
Исправление использует отдельный DEPS.chrominimum: исключены только 12
Windows CIPD путей chrome/chromium × arm64/x86/x86_64 × текущий/sans_iid.
Исходный DEPS проверяется по закреплённому SHA-256 и не изменяется; в его
копии ровно 12 соответствующих значений словаря заменяются на None.
Штатный gclient revinfo подтвердил URL/revision=null для всех этих записей,
активных тестовых updater-пакетов — 0 (filtered-deps-revinfo.json).
Повторный sync с DEPS.chrominimum завершился успешно и перешёл к runhooks;
повторных обращений к заблокированному updater instance в новом журнале нет.
Это настройка получения исходников, не отключение защиты или рабочего кода
обновлятора. Quarantine/исключения Defender не изменялись, заблокированный
пакет не восстанавливался.

[configure-cef-checkout.py](../scripts/configure-cef-checkout.py) сохраняет
остальные параметры закреплённого .gclient, выбирает DEPS.chrominimum и
отказывает при чужой конфигурации или изменённом upstream DEPS.
На отдельной копии прошли первое и повторное создание конфигурации; изменение
исходного DEPS было отклонено с сохранением прежней .gclient.
Download теперь явно возобновляет gclient sync: существующий Chromium HEAD
после прерванной загрузки ещё не означает наличия всех зависимостей.
Также явно выполняются CEF runhooks patch и gclient runhooks, которые upstream
automation может пропустить при возобновлении shallow checkout.
Промежуточный gclient flatten не завершился из-за конфликта chromium_revision
в upstream Dawn; успешная проверка графа выполнена через gclient revinfo.
Текущий повторный процесс пишет cef-build-filtered.log/cef-build-filtered-error.log;
текущий этап по-прежнему находится в source-build-state.json.

ListAccounts-патч применён и к фактическому checkout Chromium на NVMe:
итоговый SHA identity_manager.cc совпал с metadata (80323362…c36c0c6), diff
содержит 3 добавленные/6 удалённых строк. Исходный DEPS сохранил SHA
dc1d7007e7d992729d3d34b79c2443971cd07029c5599856a16ddecd445c532d.
Это применение исходного патча, ещё не компиляция или runtime-проверка.

### Инициализация Windows launchers depot_tools

Runhooks завершились, но первая генерация GN остановилась из-за отсутствия
python3_bin_reldir.txt. gclient/vpython уже работали, однако gn.bat использует
отдельный python-bin launcher. Выполнен штатный bootstrap/win_tools.bat из
закреплённой ревизии depot_tools; файл создан, commit инструментов остался
1eb46f8b23b4c6b3caa2be8e05999b6d1f4d0253. Это не обновление исходников tools.
Build-рецепт теперь выполняет эту инициализацию при отсутствии launcher marker.
Лог: depot-bootstrap.log. Повторная генерация/компиляция запущена отдельно:
cef-compile.log и cef-compile-error.log; этап — source-build-state.json.
Все 116 CEF-патчей повторно проверены (уже применённые пропущены, ошибок нет).
Повторный GN прошёл: 34122 targets из 5032 файлов; после него проверка нашего
патча повторно прошла, началась фактическая C/C++ компиляция libcef/bootstrap.
Сборщик сообщил offline mode; ограничение параллелизма — 8 задач.

Предпочтение владельца: последующие длительные загрузки/сборки запускать в
видимом окне, чтобы был понятен ход работы. Для уже запущенной компиляции
открыто отдельное видимое PowerShell-окно с живым журналом; сам процесс
не перезапускался. Скрипт окна: .local/ai-source-154/show-build-progress.ps1.
Закрытие окна просмотра не прерывает существующую компиляцию. Следующие
запуски должны использовать видимое окно с самого начала.

После компиляции CEF нужны NetLog fresh/prepared, JS/HTTP cookies и формы,
вход на сайты, HTTPS/недоверенный TLS, PDF и фактические sandbox-токены.
Проверки stock-оболочки не заменяют эти испытания собственного CEF.
