## Протокол до основной серии

Используются неизменные браузеры и fixtures из частного переносимого комплекта
`.local/comparison-kit-20261024`. Приложение, CEF, защитные флаги и рабочие
профили не меняются. Отдельный запускатель расположен в
`.local/resource-comparison-ready-20261024/START-RESOURCES.cmd`.

Подготовка создаёт синтетический профиль каждого браузера, открывает локальную
страницу с 200 карточками и штатно закрывает окно. Каждая следующая попытка
получает отдельный клон этого состояния в Windows TEMP на C:. Это одинаковая
процедура подготовки, а не побайтово одинаковый профиль разных браузеров.
Копирование профиля и проверка хешей исключены из таймера запуска.

| Сценарий | Повторов на браузер | Интервал |
|---|---:|---|
| Запуск | 10 | От spawn до получения HTTP-сигнала страницы после двух rAF |
| Простой | 5 | 5 с стабилизации, затем 30 с |
| Видео | 5 | 10 медиасекунд прогрева, затем 60 с |
| Игра | 5 | 10 с после загрузки сцены, затем 60 с |

Одинаковый iframe 1000×600, DPR/scale=1, видимый и с фокусом. Порядок
CM/UC/Chrome, UC/Chrome/CM, Chrome/CM/UC сдвигается по кругам. Старт измеряется
с прогретым кэшем ОС: это не холодный запуск и не первый запуск пустого профиля.
Сигнал двух rAF не подтверждает физический показ пикселей.

Для запуска требуется фокус/геометрия в момент готовности. Во время простоя
проверяются секундные отсчёты и события focus/visibility/resize; видео и игра
сохраняют прежние проверки плавности. Неудачные попытки остаются в отчёте,
автоматических повторов нет. Ошибка очистки останавливает дальнейшие запуски.

## Ресурсы и границы метода

Кратковременный PowerShell-наблюдатель раз в секунду читает Windows process
counters: PrivateMemorySize64, WorkingSet64, TotalProcessorTime. Учитываются
процессы текущего Windows-сеанса с executable внутри каталога закреплённого
runtime, включая вспомогательные exe из этого каталога. Выводятся private bytes
и working set отдельно; общие страницы могут повторно учитываться в working set.
Это не строгий обход родительского дерева: процессы вне каталога и короткоживущие
процессы между отсчётами не учитываются. Для каждого обнаруженного процесса
удерживается Windows QUERY_LIMITED_INFORMATION handle; GetProcessTimes читает
конечный CPU и после выхода. PID сопоставляется вместе со временем создания.
CPU нового процесса учитывается с рождения, если оно попало после предыдущего
отсчёта. Если процесс появился без пригодного начального счётчика или потерян
его конечный счётчик, ресурсный замер отклоняется. Все handles закрываются
при завершении наблюдателя.

CPU: сумма приращений user+kernel времени процессов / длительность между
отсчётами. 100% one-core означает одно полностью занятое логическое ядро;
machine дополнительно делится на число логических процессоров. Простой CPU
около нуля может давать большие, практически малозначимые относительные проценты.

Границы задаёт страница HTTP-маркерами; по 1,5 с с краёв отбрасывается для
снижения погрешности доставки. Это не точная синхронизация времени GPU/дисплея.
Разрыв отсчётов >2,5 с или менее 20 отсчётов отклоняет ресурсный замер.
Сохраняются расходы наблюдателя (CPU/private bytes/длительность чтения),
они не вычитаются из результата. Постоянной службы нет, новых зависимостей
приложения и внешних сетевых функций нет. Наблюдатель сам может влиять на тест;
отдельный проход без него для оценки возмущения пока не предусмотрен.

Отчёт содержит все значения, медиану, минимум/максимум и абсолютную/процентную
разницу CM с каждым соперником. Проценты не заменяют разброс, проверки плавности
и пригодности попыток. GPU load, энергопотребление, интернет-сайты, фоновые
службы вне каталогов и старое железо этой серией не измеряются.

## Запуск владельцем

Основную серию запускать в тестовой Windows-учётке. Рабочий Windows-сеанс
годится для технического пилота, его результаты не смешивать с основной серией.
После начала не переключать окна и не работать на ПК. Предварительная
длительность полной серии — около 50 минут; фактическая зависит от запусков.

```cmd
cd /d E:\UnityProjects\ChroMinimum\.local\resource-comparison-ready-20261024
START-RESOURCES.cmd --suite
```

Без аргументов выполняется только preflight, браузеры не запускаются.
`--pilot` выполняет по одной попытке каждого сценария на браузер.
Отчёты: `reports/<UTC>/run.json`, `aggregates.json`, исходные измерения
по каждой попытке. Браузерные TEMP-профили сохраняются, не удаляются автоматически.
Переносимый комплект браузеров должен оставаться рядом; Node берётся из него.

## Статус проверки

Добавлены тесты формул, смены PID, разрывов выборки, фильтрации неудачных попыток,
геометрии и порядка браузеров. Native resource sampler проверен на собственном
Node-процессе: 5 отсчётов, процесс найден во всех, ошибок нет. Preflight вне
песочницы прошёл. В песочнице CIM отклонён Windows access denied до запуска
браузеров; для настоящего Windows пользователя такое ограничение агента не
является условием теста.

Технические пилоты выполняются в рабочем Windows-сеансе и не являются основной
серией. Первая подготовка CM превысила 15-секундный лимит закрытия; процесс
позднее завершился самостоятельно. В следующем пилоте подготовка/запуск всех
трёх, idle CM/UC прошли, idle Chrome не запросил страницу до watchdog.
Отдельный повтор Chrome был скрыт/без фокуса и отклонён. Для интерактивных
браузеров убран SW_HIDE (утилиты остаются скрытыми); причинная связь с первым
тайм-аутом не установлена. Следующий Chrome idle сохранил видимость, но был
отклонён старым строгим правилом смены процессов. Это послужило основанием
добавить удержание CPU handles. CM video/game с ресурсными отсчётами и
аппаратным ANGLE прошли; полный трёхбраузерный пилот пока не заявлен прошедшим.

После доработки видимый Chrome idle прошёл: focus/visibility пригодны,
27 ресурсных отсчётов; в конце 8 живых процессов и 12 сохранённых CPU handles,
20 отсчётов содержат счётчики уже завершившихся процессов. Ошибок наблюдателя
нет, browser exit=0. Всего 33 автоматических теста прошли. Эти пилоты подтверждают
сбор/браковку данных, но не являются основанием заявлять экономию CM.
Полная серия в тестовой Windows-учётке ещё не выполнялась.

Исходники упаковки: `scripts/build-resource-kit.cjs`; запуск из корня
репозитория `node scripts/build-resource-kit.cjs`. Существующий каталог
не перезаписывается. В упакованном комплекте проверяются отдельный manifest
16 файлов измерителя, закреплённый hash manifest браузерного комплекта,
все 398 файлов браузерного комплекта и хеши входных fixtures.

Финальный комплект собран в `.local/resource-comparison-ready-20261024`.
Preflight прошёл из C:\Windows\Temp с PATH только Windows/System32; PowerShell
и taskkill выбираются абсолютными системными путями, установленный Node не
требуется. До исправления зависимости от PATH одна попытка preflight не нашла
PowerShell и завершилась до запуска браузеров; этот комплект сохранён отдельно.
Реальный START-RESOURCES.cmd --preflight-only завершился кодом 0. Именно
упакованный startup CM с новым клоном профиля прошёл focus/geometry и штатно
закрылся. Проверка diff whitespace затронутых файлов прошла.
