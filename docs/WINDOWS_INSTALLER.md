## Установка владельцем

Локальный артефакт: `dist/ChroMinimum-0.0.1-alpha.3-local-setup-x64.exe`.
Размер 157915246 байт (около 150,6 МиБ). SHA-256:

```text
BE82B40460A8B8BE684C7AF63D10034E880ADCB8637CE43D895B8290F45FF0FF
```

Это локальная неподписанная Authenticode сборка, не опубликованный релиз.
CEF 154.0.34 / Chromium 154.0.8037.98. Приватный ключ обновлений не читался,
публичный ключ не заменялся. Переданная пользователю сборка не использует
fixture-ключи предыдущих модульных экспериментов.

По умолчанию программа ставится в `%LOCALAPPDATA%\Programs\ChroMinimum`,
профиль/кэш/cef.log — отдельно в `%LOCALAPPDATA%\ChroMinimum`. Установщик
не требует администратора. Portable-поставки без installation.json сохраняют
прежний путь; существующие профили не переносятся автоматически.
Для тестов сохраняется явное переопределение CHROMINIMUM_DATA_DIR.

В компонентах можно оставить только ядро и английский либо добавить русский.
При выборе русского Settings.locale=ru; иначе en-US. Это язык встроенного CEF,
собственные подписи кнопок Rust-интерфейса пока остаются русскими.

Установщик регистрирует ChroMinimum в «Открыть с помощью» для HTML, HTM и PDF и в списке приложений по умолчанию. Регистрация выполняется всегда; приложение не назначается по умолчанию и не заявляет поддержку других расширений. Команда `Applications\chrominimum.exe` использует `--open "%1"`.

Для уже установленной alpha.3 запустите скрипт из корня репозитория в той же учётной записи Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\register-openwith.ps1
```

Скрипт находит exe в LocalAppData, добавляет только HKCU-записи и не меняет UserChoice.

1. Windows → Параметры → Приложения → Приложения по умолчанию → ChroMinimum.
2. Выбрать ChroMinimum для `.html`, `.htm`, `.pdf`.

На последней странице мастера есть необязательный переход к этим настройкам.
Регистрации HTTP/HTTPS как браузера по умолчанию в этой версии нет.

Команда ассоциации: `"<install>\chrominimum.exe" --open "%1"`. Загрузчик проверяет
существование HTML/PDF, преобразует путь в file URL и кодирует UTF-8/пробелы/#/%.
Имя файла не исполняется через cmd/PowerShell и не становится Chromium-флагами.
При повторном открытии с тем же профилем CEF передаёт запрос уже работающему
процессу; приложение создаёт собственное окно с адресной строкой. Штатный
NORMAL_EXIT_PROCESS_NOTIFIED обработан как успешная передача, а не ошибка запуска.
В основе — комментарии CefBrowserProcessHandler/CefGetExitCode из заголовков
именно собранного CEF 154 и закреплённые Rust bindings.

## Обновления и удаление

Эта первая установка использует прежний подписанный канал format=1.
Модульный format=2 не опубликован и не включён автоматически. Следующее обновление
может вернуть полный комплект языков/прежний адаптер; выборочная сетевая доставка
и сохранение выбранного языка после такого обновления ещё не приняты.
Нельзя считать модульный обновлятор завершённой функцией этого установщика.

Удаление через Windows убирает установленные файлы, ярлыки и собственные значения
регистрации. Профиль сохраняется. Созданные позднее обновлятором core/vN и служебные
state/lock-файлы не включаются в рекурсивную очистку и могут остаться в каталоге
программы. Готовой миграции/полной очистки обновлённых установок пока нет.
Не используются UninstallDelete с рекурсивным удалением каталога программы/профиля.
Установщик не принудительно закрывает приложения и не запускает браузер после
тихой установки.

## Воспроизводимая сборка

Recipe: `installer/windows.iss`. Использован официальный Inno Setup 6.7.3,
загруженный по ссылке [JRSoftware](https://jrsoftware.org/isdl.php).
Перед запуском его Authenticode проверен: Valid, Pyrsys B.V. Компилятор установлен
для текущего пользователя в `.local/installer-tools/inno` без ярлыков/ассоциаций.
Это зависимость сборки установщика, не зависимость/служба браузера.
Рецепт регистрации следует [Microsoft Default Programs](https://learn.microsoft.com/en-us/windows/win32/shell/default-programs):
HKCU Capabilities/RegisteredApplications, общий пункт Applications\chrominimum.exe и собственные ProgID/OpenWithProgids.
UserChoice и чужие значения ассоциаций не записываются.

```powershell
.\scripts\build-installer.ps1 -Iscc '<path-to-ISCC.exe>'
```

Скрипт собирает Release-приложение, создаёт новый payload и компилирует setup.
`-Runtime <prepared-runtime>` позволяет явно использовать уже собранный runtime,
а `-TestInstall` создаёт отдельную тестовую идентичность.
Stager `scripts/stage-installer.py` копирует строгий список runtime-файлов из
package-components.py, только en-US/ru, лицензии и загрузчик; исключены профили,
логи, PDB, статические библиотеки и лишние языки. Иконка применяется до фиксации
хешей payload-inspection.json. Данные для генерации installation.json — отдельные
строгие конфигурации; они не содержат исполняемого кода или секретов.

Финальный payload этой сборки: `.local/installer-final-payload-2026-10-20`.
Сборка создавалась локально, CI/публикация установщика не добавлены.

## Проверки и стоимость

Тестовый вариант имеет отдельные AppId, ChroMinimumInstallerTest ProgID/Capabilities,
ярлык и запись удаления. Программа владельца не устанавливалась: владелец выбрал
установить её самостоятельно. Тесты запускают отдельный TestInstall на C: и
подменяют LOCALAPPDATA только окружению тестового процесса, чтобы не использовать
реальные данные пользователя. Реестр UserChoice сравнивается до/после.

```powershell
python scripts/test-windows-installer.py --installer <test-setup.exe> --output <new-test-directory-on-C>
```

До сборки финального рецепта проверены тихая установка EN/RU, регистрация,
HTML с кириллицей/пробелами/#/%, PDF, отдельный профиль, удаление и сохранение
контрольного файла данных. Финальный прогон дополнительно проверяет relaunch
HTML → PDF в уже открытом экземпляре и две собственные панели/два окна.
Команды берутся из фактически установленного ProgID; это воспроизведение shell
команды, а не автоматический выбор приложения в UI Windows.

Финальный TestInstall прошёл оба языка: EN — 4 pak, HTML → PDF при уже открытом
экземпляре, две собственные панели/два окна; RU — 8 pak с fallback и отдельное
открытие PDF. Оба родительских smoke завершились с 0, около 31,2 секунды с учётом
намеренного 30-секундного окна теста. После удаления отсутствуют launcher,
installation.json, собственные ProgID/Capabilities/RegisteredApplications и
OpenWithProgids-значения; sentinel данных сохранён, UserChoice не изменён.
Процессов chrominimum после серии нет. Установленные файлы тестового варианта:
389214869 байт EN, 390420624 байт RU, включая деинсталлятор/служебные файлы,
без профиля. Это около 371,2 и 372,3 МиБ.

Отчёты скопированы в `.local/windows-installer-test-2026-10-20/result.json`,
en-US/ru с журналами установки, запуска и удаления. SHA-256 финального тестового
setup: `384d7ad7f48a9947dacb8e9dbbd0f282d745fadbf133e3d5704047dc0074c2e1`.
Он отличается от основного только макросами TestInstall (имена/идентичность/
регистрация/выходное имя), runtime и launcher взяты из одного payload.
Основной вариант скомпилирован отдельно; его установка владельцем ещё не выполнена.

Дополнительно на том же runtime/DLL с отдельным NVMe-профилем прошёл полный
HTTP/JS/Enter/back/forward/reload/resize/maximize/minimize smoke, код 0,
payload не изменён. Первый GET наблюдался через 0,512 с; это одиночная диагностическая
проверка, не сравнительный замер скорости. Отчёт сохранён рядом в navigation/.

Пройдены 25 обычных Rust-тестов обновлятора (два fixture-теста пропускаются по
умолчанию), clippy обоих проектов с -D warnings, rustfmt, Release-сборки,
синтаксис Python/PowerShell и diff-check. Все 33 хеша payload повторно сверены
после изменения иконки. Визуальная проверка мастера и выбор умолчаний через UI
не подменяются этими автоматическими тестами.

Создание установки/регистрации происходит один раз; сетевых загрузок у setup нет.
Постоянной службы, автозапуска при входе и фонового процесса установщика нет.
Дополнительное окно создаётся только по явному открытию файла и имеет обычную
стоимость ещё одной страницы CEF. RAM/CPU нового окна отдельно не измерены.
Release-загрузчик: 2390016 → 2398208 байт, DLL: 712192 → 715264 байт относительно
предыдущих локальных артефактов, не чистых парных сборок. Сравнительных замеров
запуска пока нет; отдельная проверка HDD/NVMe сохраняется по
[HTTP_STARTUP_DIAGNOSIS.md](HTTP_STARTUP_DIAGNOSIS.md).

Ограничения: визуальная приёмка мастера/Windows Default Apps, реальных нажатий
«Открыть с помощью», панели/поиска/масштаба PDF и глубокая security-приёмка остаются
отдельными. Успешный PDF load не доказывает все функции просмотрщика.
Обнаруженные фоновые обращения Chrome-style CEF остаются отдельной задачей аудита.
