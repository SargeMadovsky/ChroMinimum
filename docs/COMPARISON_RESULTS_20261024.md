# Результат контрольной серии CM / UC / Chrome — 2026-10-24

Серия завершилась полностью: 37 мин 30 с, 33 попытки, 31 принята, 2 отклонены.
Все три сценария имеют completed=true. allStagesAccepted=false объясняется
WebRTC: отказ UC и непригодный по фокусу замер Chrome; это не обрыв серии.

## Видео и игра

| Показатель | CM | UC | Chrome |
|---|---:|---:|---:|
| Принято минутных видео-попыток | 5/5 | 5/5 | 5/5 |
| Delta dropped video frames, сумма | 0 | 0 | 0 |
| Waiting / stalled в окнах видео | 0 / 0 | 0 / 0 | 0 / 0 |
| Принято минутных игровых попыток | 5/5 | 5/5 | 5/5 |
| Медиана p99 render-loop интервала, мс | 6,2 | 6,2 | 6,2 |
| Игровые интервалы >2 / >4 периодов 165 Hz | 0 / 0 | 0 / 0 | 0 / 0 |

Видимая измеряемая область одинаковая, 1000×600, DPR/scale=1. В игре
ANGLE RX580/D3D11. Каждая попытка штатно закрыла браузер (lifecycle exit=0).
Порядок браузеров сдвигался по кругам. Видеофайл и игровая сцена закреплены
хешами. Пересчёт всех 33 summary из observation.json упакованными измерителями
совпал с сохранёнными summary; несовпадений нет.

В этих сценариях заметного различия по собранным показателям плавности нет.
CM справился со всеми принятыми видео/игровыми попытками. Это поддерживает
пригодность текущей основы для этих задач, но не доказывает превосходство.
Вызовы рендера идут примерно с частотой экрана 165 Hz: запас производительности
и поведение более тяжёлых сцен этим не определены. CPU/private bytes/GPU load
и запуск не измерялись. Render callbacks не равны физическому показу кадров;
медиапропуски — счётчики браузера, не внешнее наблюдение дисплея.

## WebRTC исходной серии

- CM: принят. За 30,042 с принято 898 VP8 frames, dropped=0,
  video packet loss delta=0, 1502 Opus packets; ненулевой PCM peak≈0,127.
- UC: отклонён до измерения. Source tracks есть, но у обоих peers после
  завершения gathering нет ICE candidates; readiness timeout. Причина
  отсутствия кандидатов не установлена. Это конфигурация без STUN/TURN,
  по ней нельзя объявлять все реальные звонки UC неработающими.
- Chrome: video и ненулевой PCM получены (898 frames, dropped=0), но во всех
  31 отсчётах document.hasFocus=false, visibility=visible. Blur transition
  в измеряемом окне отсутствует: фокуса уже не было к началу наблюдения.
  Владелец сообщил, что появился запрос брандмауэра; эта причина записана
  как сообщение владельца. Это не отказ видеодекодера/аудиотракта Chrome.

Код 1 WebRTC ожидаемо сохранился в полном итоговом отчёте. В исходной серии
только один WebRTC-запуск на браузер, поэтому статистического сравнения
WebRTC-производительности нет. Разрешение адаптируется (например, 320×180 →
960×540). Это локальные peers, muted output, без реальных камеры/микрофона,
интернет/NAT/TURN и проверки физического звукового вывода.

## Отдельный повтор Chrome после разрешения брандмауэра

По разрешению владельца выполнен один повтор того же executable комплекта
с новым браузерным профилем. Он прошёл: 30,039 с, 899 video frames,
dropped=0, 1502 audio packets, ненулевой PCM peak≈0,131, focus пригоден,
browser/runner exit=0.

**Этот повтор выполнен в рабочем Windows-сеансе, а не в тестовой Windows-учётке.**
Разные TEMP roots подтверждены путями launch.json; владелец также указал
на различие. Новый одноразовый браузерный профиль не заменяет новый Windows
сеанс. Повтор сохраняется только как диагностика, не добавлен к 33 попыткам
исходной серии и не подменяет отклонённый исходный Chrome.

## Условия и пределы

Windows сообщает 2560×1440@165 Hz, RX580 driver 31.0.21924.61. До сценариев
CPU snapshots: video 0/0/0%, game 3/1/0%, WebRTC 0/0/0%. Это короткие
предварительные отсчёты, не непрерывный замер нагрузки во время теста.
В общесистемных списках были сторонние процессы/службы (в том числе AnyDesk,
ShareX, FilmoraTray, updater/service процессы). По этим спискам без SessionId
нельзя установить, какой Windows-сеанс их породил или как они повлияли.
Сервис codex-windows-sandbox-service не доказывает работу интерфейса Codex.
Строгая изоляция фоновой нагрузки не подтверждена; «чистый пользователь»
не равен системе без фоновых программ.

Версии Chromium различаются: CM 154, UC/Chrome 155. Внешние окна различаются,
одинаков именно измеряемый iframe. Цена инструментирования отдельно не
измерялась. Числовой порог достаточного выигрыша владельцем не назначался;
вводить его задним числом по этим результатам нельзя.
