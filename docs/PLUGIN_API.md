# Дополнительные модули и API

Статус: требования к границам. Стабильного SDK или ABI пока нет.

## Три разных механизма

1. WebExtensions — основная сторонняя экосистема, см. EXTENSIONS_POLICY.
2. Встроенные модули Rust — доверенные функции оболочки, поставляются с браузером и включаются отдельно.
3. Возможный внешний WASM API — дополнительные возможности за пределами WebExtensions. Отложен до обоснования потребности и замеров runtime.

Не загружать сторонние Rust DLL в процесс браузера; не полагаться на стабильный Rust ABI. Обновление встроенного модуля в первой реализации может требовать обновления браузера. Код отключённого встроенного модуля может оставаться в бинарнике, но не создаёт активные обработчики, потоки и таймеры.

## Предлагаемый контракт

Идентификатор и версия модуля; диапазон совместимости host API; перечень возможностей; команды; подписки на события; собственное хранилище; вклад в меню/панели через host. Контракт проектируется и версионируется до выпуска стороннего SDK.

Модуль не получает указатели движка, произвольный SQL к профилю или доступ к чужим данным. Core выдаёт непрозрачные PageId/WindowId и проверяет их при каждой операции. UI вкладок использует общее управление страницами, а не создаёт параллельную модель.

## Состояния

Обнаружен → проверен → разрешён → активируется → работает → останавливается → отключён. При ошибке — явное состояние с причиной. Повторное включение не создаёт дублирующих подписок. Остановка освобождает ресурсы и ограничена временем; для доверенного кода внутри процесса невозможно гарантировать принудительное безопасное прерывание произвольного зависания.

## Первая приёмка API

Пробный встроенный модуль добавляет команду «Показать адрес», получает разрешённый URL и снимает обработчики при отключении. Затем реализуется панель вкладок. Внешний тестовый плагин появляется только после выбора изоляции host; этот тест не заменяет приёмку WebExtensions.
