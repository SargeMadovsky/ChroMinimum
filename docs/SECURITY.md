# Безопасность

Статус: проект требований, не отчёт об аудите. Публичной безопасной сборки пока нет.

## Угрозы и доверие

Недоверенные стороны: веб-страницы, скачанные файлы, расширения, пакеты обновлений и входящие IPC. Риски: выход из renderer, кража данных профиля, confused deputy через API оболочки, подмена обновления и повышение прав расширением.

Привилегированная часть: browser process, ядро, встроенные модули и updater. Rust уменьшает часть ошибок памяти, но не устраняет ошибки FFI, C++ движка и логики разрешений.

## Обязательные меры

- Sandbox, проверка TLS и изоляция сайтов остаются включёнными; фактический режим проверяется на каждой платформе.
- Разрешения камеры, микрофона, местоположения, уведомлений и доступа к файлам привязаны к origin и профилю, видимы и отзываемы.
- IPC валидирует отправителя, полномочия, размеры и жизненный цикл объектов.
- Загрузки не исполняются автоматически; имена и пути нормализуются, запись вне выбранного места не допускается.
- Данные приватного профиля не смешиваются с обычным; отдельно документировать неизбежные следы ОС и сетевой инфраструктуры.
- Пароли и токены не попадают в логи; секреты защищаются средствами ОС, если их хранение входит в реализованный объём.
- Привилегированные внутренние страницы отделены от веб-origin; навигация с сайта не даёт им дополнительных прав.

## Обновления

Обновления движка обязательны с первого прототипа как процесс сопровождения; автоматический updater реализуется отдельно. До него документируется безопасная ручная замена сборки.

Для updater необходимы: аутентификация manifest и пакета, проверка подписи и целостности до установки, атомарное переключение, восстановление после прерывания и защита от непреднамеренного отката на уязвимую версию. Ключ подписи не хранится в репозитории. Аварийный rollback использует явно разрешённую безопасную сборку.

При каждом обновлении: оценка upstream security fixes → перенос патчей → сборка → sandbox/extension regression tests → подписанная поставка. Допустимое окно задержки и ответственный определяются до публичного использования; просроченные security fixes блокируют обычный релиз.

## Выпуск и сообщения об уязвимостях

До публичного релиза выбрать закрытый канал сообщений и добавить реальный контакт; не выдумывать security email. Независимое ревью требуется для FFI, IPC, расширений, updater и профилей. Внутреннее ревью агентом не объявляется независимым аудитом.
