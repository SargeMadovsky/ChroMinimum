## Изолированные профили Windows, 2026-10-19

Подготовлены три пустых каталога в игнорируемом Git `test-profiles/comparison-2026-10-19/`: `chrome`, `ungoogled-chromium` и `chrominimum/profile`. В `chrominimum` скопированы исполняемые файлы и ресурсы текущего `target/release-bundle`, без существующих профилей и журналов. Это отдельная копия сборки; последующая пересборка автоматически её не обновляет.

Запуск из корня репозитория, по одному браузеру:

```powershell
.\scripts\run-benchmark-profile.ps1 -Browser chrominimum
.\scripts\run-benchmark-profile.ps1 -Browser ungoogled-chromium
.\scripts\run-benchmark-profile.ps1 -Browser chrome
# Для Chrome, установленного в другом месте:
.\scripts\run-benchmark-profile.ps1 -Browser chrome -Executable 'C:\path\to\chrome.exe'
```

Chrome и ungoogled-chromium получают отдельный `--user-data-dir` согласно [документации Chromium](https://www.chromium.org/developers/creating-and-using-profiles/). ChroMinimum использует профиль рядом с отдельной копией exe; дополнительно задаётся `CHROMINIMUM_DATA_DIR`, поддерживаемый текущими исходниками. Защитные настройки не изменяются. Скрипт не очищает и не восстанавливает профили: после первого запуска они уже не пустые.

Выполнена первичная инициализация без входа и импорта: все три браузера создали тестовые данные и открыли окно `about:blank`. Chrome и ungoogled-chromium создали `Default` в заданных каталогах, ChroMinimum — `chrominimum/profile`. Проверено наличие окна средствами ОС; содержимое страницы и настройки через UI не проверялись. Первый запуск внутри ограничений среды агента вызвал падение GPU Chrome; повторный запуск вне этих ограничений открыл окно успешно, без изменения sandbox или GPU-флагов браузера. Замеры из ограниченной среды агента не проводить.

Для сравнения скачаны отдельные сборки в `test-profiles/comparison-2026-10-19/browsers/`; скрипт запуска по умолчанию использует именно их:

| Браузер | Версия | Источник и проверка |
|---|---|---|
| Google Chrome | 155.0.8059.85 | [Офлайн-пакет Google](https://dl.google.com/chrome/install/ChromeStandaloneSetup64.exe); Authenticode установщика и chrome.exe: Valid, Google LLC |
| ungoogled-chromium | 155.0.8059.79-1.1 | [Windows release проекта](https://github.com/ungoogled-software/ungoogled-chromium-windows/releases/tag/155.0.8059.79-1.1); SHA-256 ZIP совпал с digest GitHub API |

Chrome извлечён из подписанного установщика, установщик и updater не выполнялись. Это обычный Google Chrome, не Chrome for Testing, но способ запуска без установки отличается от штатной установленной поставки. Архивы извлечены локальной консольной версией [7-Zip 26.04](https://www.7-zip.org/download.html), без установки зависимости проекта. Источники и SHA-256 загрузок сохранены в локальных `chrome-download.json` и `ungoogled-download.json`. Старые установленные браузеры и личные профили не использовались.

Версии движков различаются: такие результаты характеризуют эти конкретные сборки, а не чистое влияние оболочки. Полная ручная проверка первого запуска, отсутствия диалогов и расширений ещё нужна. Первый автоматизированный предварительный замер описан ниже; viewport и готовность fixture в нём проверены программно. Инициализированный профиль уже не является пустым; для серии повторов используется одно фиксированное сохранённое состояние.

После штатного закрытия окон подтверждено отсутствие процессов из тестовых копий; у Chrome и ungoogled-chromium `profile.exit_type` равен `Normal`. Сохранены копии профилей в локальном `baseline-initialized/{chrome,ungoogled-chromium,chrominimum}`. Последний каталог содержит непосредственно профиль ChroMinimum (соответствует рабочему `chrominimum/profile`). Это состояние после инициализации, до ручной приёмки; его не следует считать окончательным эталоном замеров.

## Первый локальный стенд Windows

`scripts/benchmark-browsers.py` запускает только подготовленные тестовые копии, создаёт уникальный каталог результатов и для каждого запуска копирует сохранённый профиль в новый каталог. Существующие профили не удаляет. Если тестовый экземпляр уже работает, скрипт отказывается продолжать. Изменений приложения для замеров нет.

Инструменты измерения устанавливаются отдельно от приложения в игнорируемый `.local`: psutil для процессов, памяти и CPU, Matplotlib для графиков. Воспроизводимый запуск из корня проекта:

```powershell
python -m pip install --target .local/benchmark-python -r scripts/benchmark-requirements.txt
python scripts/benchmark-browsers.py --runs 10 --output .local/browser-benchmark-2026-10-20
python scripts/plot-browser-benchmark.py .local/browser-benchmark-2026-10-20 --output docs/reports/browser-comparison-2026-10-20
```

Каталоги вывода должны быть новыми. Запускать из обычного интерактивного Windows-сеанса, вне ограничений среды агента. Скрипт временно закрепляет окно поверх других окон и пытается передать ему фокус. Фокус во время простоя только фиксируется, не является непрерывно контролируемым условием; видимость и viewport проверяются при отсчётах. Это предварительный стенд рабочего компьютера, не изолированная лаборатория.

После прерывания можно добавить `--resume` к команде измерения: успешные повторы пропускаются, а повторная попытка получает новый каталог без удаления неудачной. Проверяются совпадение хешей исполняемых файлов, DLL ChroMinimum, fixture и числа повторов. Не следует объединять так серии с разными внешними условиями. При первоначальной серии один готовый прогон Chrome отклонён из-за дополнительного требования фокуса в момент приёма сигнала; после снятия этого требования серия продолжена. Остальные условия и измерительная формула не менялись, результаты неудачной попытки не включены.

Ещё одна попытка ChroMinimum в этой серии превысила лимит штатного завершения 30 секунд. Позднее подтверждено самостоятельное завершение процессов, без принудительного закрытия. Попытка исключена и повторена; ошибка сохранена отдельно в `failed-attempts.json`. График успешных повторов не отражает надёжность закрытия.

Сценарий: детерминированная локальная HTML-страница с 200 карточками, без внешних ресурсов. Калибровка каждого браузера устанавливает viewport 1000×600 CSS px. Готовность фиксирует HTTP-сообщение от JavaScript после двух `requestAnimationFrame`; это не подтверждение физического показа пикселей монитором. Время запуска включает создание процесса, управление окном, загрузку и этот сигнал. Результаты калибровки исключаются из серии. Это запуск с прогретым кэшем ОС, который специально не сбрасывается; профиль перед каждым повтором восстанавливается из одного состояния.

После готовности — 5 секунд стабилизации и 6 отсчётов с шагом 1 с (около 5 секунд простоя). Память каждого запуска — медиана отсчётов. Суммируются процессы с точным путём тестового exe, включая renderer/GPU/utility и crashpad того же exe; PID, родитель, команды и значения каждого процесса сохраняются. Отдельные службы и вспомогательные exe, если появятся, этим методом не включаются. CPU — приращение user+kernel времени с учётом PID и времени создания, нормированное на длительность и число логических CPU. Краткоживущие процессы между отсчётами могут быть пропущены. Средняя загрузка CPU всей системы сохраняется как индикатор посторонней нагрузки.

Порядок браузеров чередуется ABC/BCA/CAB. Закрытие — обычное сообщение окну; принудительное завершение для успешного результата не применяется. Незавершившиеся процессы, отсутствие сигнала готовности или изменение viewport прерывают серию. Уже полученные успешные результаты сохраняются после каждого запуска. Отчёт содержит все повторы, медиану и минимум–максимум, PNG/SVG-график, CSV, JSON и сам HTML fixture.

Метрики памяти соответствуют [PROCESS_MEMORY_COUNTERS_EX](https://learn.microsoft.com/en-us/windows/win32/api/psapi/ns-psapi-process_memory_counters_ex): PrivateUsage — private committed bytes, WorkingSetSize включает общие страницы. CPU соответствует [GetProcessTimes](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getprocesstimes). Private bytes не является физической RAM, а сумма working set не является уникальной физической памятью.

## Предварительные локальные результаты, 2026-10-20

Выполнено 30 успешных запусков: по 10 каждого браузера, 180 отсчётов ресурсов. Все отсчёты содержат процесс renderer; суммы памяти проверены по сохранённым значениям процессов. После серии тестовых процессов не осталось. Хеши exe совпали с зафиксированными до измерений. Две неуспешные попытки описаны выше и в локальном журнале; их результаты в медианы не включены.

Машина: AMD Ryzen 7 3700X, 8 ядер / 16 логических CPU, доступный ОС общий объём RAM 31,9 ГиБ, Windows 10 build 19045. Использовалась уже активная схема `ChrisTitus - Ultimate Power Plan`; её настройки не менялись. GPU и накопитель отдельно не идентифицированы. Загрузка CPU всей системы во время интервалов менялась от 1,3 до 26,6%; это предварительные измерения на рабочем ПК. Фокус принадлежал браузеру в 157 из 180 отсчётов, а не непрерывно во всех прогонах.

Нулевой CPU в отдельных коротких интервалах не доказывает полного отсутствия вычислений: счётчики имеют конечную точность. ## Сбор результатов

Для старта — не менее 10 повторов; длительные сценарии — не менее 5. Публиковать отдельные значения, медиану и диапазон; p95 интерпретировать только при достаточном числе наблюдений. Указывать длительность простоя и стабилизации.

На Windows не складывать working set процессов как уникальную физическую память: shared pages могут учитываться повторно. Публиковать private bytes и working set раздельно для всего дерева, с оговоркой метода; не называть их взаимозаменяемыми RAM.

Первый baseline появляется на этапе 00. После него устанавливаются реалистичные бюджеты и пороги регрессии отдельным решением. Выгрузка вкладок не должна терять формы, ломать аудио, загрузки или активные соединения без предсказуемой политики исключений.
