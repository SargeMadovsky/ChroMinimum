# Измерение производительности

Статус: методика. Базовых значений и обещаний экономии пока нет.

## Условия

Одинаковая машина, ОС, питание, версии Chromium по возможности, набор сайтов, состояние профиля/кэша, viewport, GPU и защитные настройки. Записывать различия конфигурации эталона. Отдельно тестировать минимальный режим, одинаковые расширения и каждый дополнительный модуль.

| Сценарий | Измерения |
|---|---|
| Первый запуск процесса с прогретым кэшем ОС | Время до готовности UI и первой страницы |
| Холодный запуск после контролируемой подготовки | Те же метрики; способ очистки кэша явно указан |
| Пустая страница и простой | Память всего дерева процессов, CPU, потоки и фоновые обращения |
| 10 фиксированных страниц | Память, CPU, процессы и отзывчивость |
| Фоновая страница/выгрузка | Освобождение памяти, время восстановления, сохранность форм |
| Видео | CPU/GPU, dropped frames и плавность |
| Расширения/модули | Приращение ресурсов и задержек, стоимость фильтрации |

## Сбор результатов

Для старта — не менее 10 повторов; длительные сценарии — не менее 5. Публиковать отдельные значения, медиану и диапазон; p95 интерпретировать только при достаточном числе наблюдений. Указывать длительность простоя и стабилизации.

На Windows не складывать working set процессов как уникальную физическую память: shared pages могут учитываться повторно. Публиковать private bytes и working set раздельно для всего дерева, с оговоркой метода; не называть их взаимозаменяемыми RAM.

Первый baseline появляется на этапе 00. После него устанавливаются реалистичные бюджеты и пороги регрессии отдельным решением. Выгрузка вкладок не должна терять формы, ломать аудио, загрузки или активные соединения без предсказуемой политики исключений.
