# Правила работы над ChroMinimum

Эти правила действуют для всего репозитория.

- Перед работой прочитай README.md, docs/TASKS.md и документы по своей задаче.
- Соблюдай PRODUCT.md и EXTENSIONS_POLICY.md; предложения прежнего GPT не являются доказательствами.
- Реализуй одну ограниченную задачу за раз; не делай несвязанный рефакторинг.
- На этапе документации не создавай каркас приложения и зависимости без задачи на реализацию.
- CEF, cef-rs, GUI toolkit и WASM пока кандидаты. Проверяй версии и API по первичным источникам.
- Не обещай работу MV2, uBlock Origin или Firefox API без воспроизводимых испытаний.
- Не отключай sandbox, проверку сертификатов и изоляцию сайтов ради успешного запуска.
- Не добавляй телеметрию, скрытые соединения, обязательные аккаунты и выполнение стороннего нативного кода в процессе браузера.
- Храни привилегированные операции в ядре; проверяй разрешения на стороне получателя IPC.
- Не используй реальные профили, пароли и пользовательские данные в тестах.
- Предпочитай события опросу, ленивый запуск постоянным фоновым службам.
- Обосновывай зависимости; измеряй оптимизации и накладные расходы.
- Перед каждой новой функцией заранее обсуждай с владельцем влияние на запуск, память, CPU, размер поставки, фоновые процессы и сеть. Отличай ожидаемые расходы от замеров; не добавляй несогласованные функции. Подробности: .cursor/rules/performance.mdc.
- Не создавай каталоги будущих подсистем без необходимости текущего этапа.
- Изменение архитектурного решения фиксируй в docs/DECISIONS.md с причиной и последствиями.
- Для реализации выполняй подходящие проверки и ревью изменений; документацию проверяй на согласованность и ссылки.
- Различай: прочитан исходник, выполнена сборка, запущено приложение, проверено поведение.
- Не называй непроверенную функцию работающей; фиксируй ограничения и блокеры.
- Обновляй docs/TASKS.md после завершения задачи.
- Итог сообщай по-русски: результат, проверки, ограничения и следующий шаг.
